## Why

VantagePeers Cloud (multi-tenant — Claude.ai, ChatGPT, Claude Code, Codex, any MCP-capable IDE) requires an HTTP admin surface so operators can apply emergency remediation to scope profiles without direct Convex CLI access. The underlying mutation `oauth:patchScopeProfileEmergency` already ships (S1.2-mutation + S2.1 cascade); S2.2 D5 only adds the REST wrapper on the MCP server.

Day 90 canonical use-case: drop the `global` wildcard from `marie-iris-rh`, rename to `iris-rh`, and cascade-revoke all access + refresh tokens citing either name in a single atomic call with append-only audit trail.

---

## Endpoint contract

```
PATCH /admin/scope-profiles/:id
Authorization: Bearer <BEARER_SECRET_MASTER>
Content-Type: application/json
```

### Request body

| Field | Type | Required | Notes |
|---|---|---|---|
| `rename` | `string` | no | New `profileId` after patch. Triggers cascade-retarget of `oauth_clients`. |
| `fromAllowList` | `string[]` | no | Replaces existing list verbatim. |
| `namespaceReadPrefixes` | `string[]` | no | Replaces existing list verbatim. D4 enforced. |
| `namespaceWritePrefixes` | `string[]` | no | Replaces existing list verbatim. D4 enforced. |
| `cascadeRevokeTokens` | `boolean` | **yes** | When `true`, deletes all `oauth_access_tokens` + `oauth_refresh_tokens` citing either the old or the new profile name. |
| `reason` | `string` | **yes** | Audit trail hygiene. Convex enforces ≥40 chars. |

### Success response (200)

```json
{
  "patchedProfileId": "iris-rh",
  "cascadeRevokedCount": 5,
  "clientsRetargeted": 1,
  "auditLogId": "k...."
}
```

### Error mapping

| Convex / HTTP condition | Status | Body shape |
|---|---|---|
| Missing `Authorization: Bearer …` header | 401 | `{ error: "Missing Authorization header" }` (middleware) |
| Bearer present but ≠ master | 403 | `{ error: "Forbidden: admin endpoints require master token" }` (middleware) |
| Body not valid JSON | 400 | `{ error: "invalid_request", detail: "body must be valid JSON" }` |
| Missing `cascadeRevokeTokens` | 400 | `{ error: "invalid_request", detail: "cascadeRevokeTokens (boolean) is required" }` |
| Missing or empty `reason` | 400 | `{ error: "invalid_request", detail: "reason (string) is required" }` |
| Convex throw: `reason must be at least 40 characters …` | 400 | `{ error: "invalid_request", detail: "<message>" }` |
| Convex throw: `D4 violation: profile "X" cannot include …` | 400 | `{ error: "D4 violation", detail: "<message>" }` |
| Convex throw: `profile not found: <id>` | 404 | `{ error: "not_found", detail: "<message>" }` |
| Any other Convex throw | 500 | `{ error: "server_error", detail: "<message>" }` |

## Auth — BEARER_SECRET_MASTER (defence in depth)

1. **HTTP layer:** `masterOnlyMiddleware()` is already mounted on the `/admin/*` Hono sub-app and enforces the 401 / 403 split before the route handler runs.
2. **Convex layer:** the mutation re-asserts master via `requireMasterAuth(callerToken)` using the **same constant-time `timingSafeEqual`** helper imported by `createClient` (S1.5 D6 pattern, `mcp-server/src/crypto.ts`). The HTTP layer forwards `process.env.BEARER_SECRET_MASTER` as the `callerToken` argument, so a stolen middleware bypass would still hit the Convex constant-time check.

No new master-token comparison utility was introduced — the existing path is reused per task constraint.

---

## Cascade behaviour (delegated to existing Convex mutation)

- **`clientsRetargeted`** — when `rename` is set and differs from current `profileId`, every row in `oauth_clients` where `scopeProfile = oldName` is patched to `scopeProfile = newName`. No client orphans after rename.
- **`cascadeRevokedCount`** — when `cascadeRevokeTokens: true`, every `oauth_access_tokens` + `oauth_refresh_tokens` row citing either the old or the new profile name is deleted. Counted and returned.
- **`auditLogId`** — append-only `oauth_audit_log` row capturing `previousState`, `newState`, `actorTokenHash` (SHA-256 of the master token), `reason`, `cascadeRevokedCount`, `clientsRetargeted`.

Re-issue of replacement tokens is **explicitly out of scope** for D5: cascade-revoke is the immediate-safety lever; clients re-authenticate via the standard `/authorize` + `/token` flow against the patched profile. This matches the Day 90 doctrine "revoke first, re-issue via normal OAuth" and avoids a parallel emergency-token-mint surface.

## Example: Day 90 remediation call

```bash
curl -X PATCH "$PUBLIC_BASE_URL/admin/scope-profiles/marie-iris-rh" \
  -H "Authorization: Bearer $BEARER_SECRET_MASTER" \
  -H "Content-Type: application/json" \
  --data '{
    "rename": "iris-rh",
    "namespaceReadPrefixes":  ["iris/"],
    "namespaceWritePrefixes": ["iris/"],
    "cascadeRevokeTokens": true,
    "reason": "Day 90 remediation: drop global wildcard from tenant scope profile, rename to iris-rh, revoke outstanding tokens"
  }'
```
