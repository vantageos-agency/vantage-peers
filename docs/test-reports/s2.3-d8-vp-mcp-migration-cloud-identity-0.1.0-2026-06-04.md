## SECURITY UPGRADE — `masterOnlyMiddleware`

**Before (`mcp-server/src/auth.ts` L455-477 pre-S2.3 D8):**
```ts
const token = authHeader.slice("Bearer ".length).trim();
if (token !== masterToken) { /* 403 */ }
```
Direct string compare — **non-constant-time**. Short-circuits at the first
differing byte; admin endpoints leaked a timing oracle on the master token.

**After (S2.3 D8):**
```ts
const result = await validateMasterBearer(authHeader, masterToken);
if (!result.ok) { /* 401 if missing|malformed, 403 if mismatch */ }
```
Brick `validateMasterBearer` sha256-hashes both the presented token AND the
configured master secret, then compares the two digests via the brick's
`timingSafeEqual` (XOR-accumulate over equal-length byte arrays, with a dummy
HMAC on length mismatch to avoid branch-timing leaks).

Both the *length-oracle* and the *byte-oracle* on the raw master token are
closed. Coverage: all `/admin/*` routes mounted under `admin.use("*", masterOnlyMiddleware())`
in `server-http.ts` L790, including:
- `POST /admin/scope-profiles` (S2.2 D5)
- `PATCH /admin/scope-profiles/:id` (S2.2 D5)
- `GET /admin/scope-profiles` (S2.2 D5)
- All other admin OAuth endpoints

## API surface mismatches (handled, not silenced)

Per Sigma brief, surface mismatches with the brick were resolved at the
**call site**, not by relaxing brick semantics:

1. **`timingSafeEqual` (string→Uint8Array):** brick 0.1.0 takes `Uint8Array`
   (framework-agnostic byte compare). All 4 call sites (2 in server-http.ts,
   3 assertions in the test) wrapped with `new TextEncoder().encode(...)`.
   Algorithm unchanged (XOR-accumulate + dummy HMAC on length mismatch).

2. **`isMasterScope` semantics differ:** brick checks `scope === "master"`
   OR `fromAllowList.includes("*")`. Local checks `isMaster === true` OR
   `scopeProfile === "master"` OR `fromAllowList.includes("*")`. **Kept
   local `isMasterScope`** to preserve the legacy `isMaster: true` master
   bearer path (`mcp-server/src/auth.ts` L289-294 master construction).
   The brick's scope-filter helpers (passes/list/get) internally check
   `fromAllowList.includes("*")` which all VP master contexts set →
   no behavioural regression for master-bearer callers.

3. **`OAuthContext` vs `OAuthCtx`:** local type is a structural superset of
   brick's. TypeScript structural typing accepts the local type when passed
   to brick functions (extra fields ignored).
