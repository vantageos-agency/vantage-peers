## Scope

`seedDefaultProfiles` at `convex/oauth.ts:77-153` previously skipped any
catalog entry whose `profileId` already existed in `oauth_scope_profiles`
(`if (existing) continue;` at L142). When the in-code catalog drifted
relative to the persisted row — as happened with the Day 88 Nadia scope
remediation — propagating the change required a bespoke one-off migration
(`convex/migrations/patch_nadia_iris_rh_scope.ts`). This pattern is brittle,
relies on manual `bunx convex run` invocations after each deploy, and forks
the catalog source of truth between code and DB.

This sprint replaces the skip-on-exists logic with **patch-on-diff upsert
semantics** so the in-code catalog stays the SSOT and future edits propagate
cleanly through the seed mutation on the next deploy.

In scope:
- `convex/oauth.ts` — `seedDefaultProfiles` rewritten as upsert with
  per-field diff, audit log emission, structured return shape.
- `convex/oauth-seed-default-profiles-upsert.test.ts` — 9 phase tests
  (T1..T8 plus T6b) covering insert / no-op / drift-patch / preserve
  operator rows / `_creationTime` preservation / audit log shape /
  master-token gating / idempotency.
- `convex/oauth.test.ts` — 2 legacy callers migrated to the new
  `{ inserted, updated, skipped }` return shape.

Out of scope (deliberately preserved):
- `convex/migrations/patch_nadia_iris_rh_scope.ts` is **not** deleted.
  Removal is a separate decommission step once the upsert path has shipped
  in production. The migration remains a no-op once the row is renamed to
  `<client-org>`, which `seedDefaultProfiles` will now safely preserve.
- No mcp-server changes (Convex backend doctrine fix only).
- No destructive sync — rows present in the DB but absent from the catalog
  are PRESERVED.

## Behaviour

Old (skip-on-exists):

```
for each catalog seed p:
  if exists(p.profileId): continue
  else: insert(p)
```

New (patch-on-diff upsert + audit):

```
for each catalog seed p:
  existing = lookup(p.profileId)
  if not existing: insert(p) → inserted[]
  else:
    diff = fields-of(existing) ≠ fields-of(p)
    if diff is empty: → skipped[]
    else:
      ctx.db.patch(existing._id, diff + updatedAt)
      ctx.db.insert(oauth_audit_log, {
        eventType: "seed_upsert",
        actorTokenHash,
        targetProfileId: p.profileId,
        previousState: {profileId, fromAllowList, namespaceReadPrefixes, namespaceWritePrefixes},
        newState: {profileId, fromAllowList, namespaceReadPrefixes, namespaceWritePrefixes},
        reason: "seedDefaultProfiles upsert — catalog drift patched (S3.4 B4)",
        cascadeRevokedCount: 0,
        clientsRetargeted: 0,
        createdAt: now,
      })
      → updated[]
return { inserted, updated, skipped }
```

Notes:
- `_creationTime` and `createdAt` are preserved across patches (only
  diverging fields are written, plus `updatedAt`).
- `description` drift IS patched in the row but is intentionally NOT part
  of the `oauth_audit_log` forensic shape, which is constrained by schema
  to `{profileId, fromAllowList, namespaceReadPrefixes, namespaceWritePrefixes}`.
- `cascadeRevokedCount` and `clientsRetargeted` are `0` for seed upserts —
  changing seed catalog content does NOT revoke active tokens or retarget
  clients (those cascades remain the responsibility of
  `patchScopeProfileEmergency`).
- Master-token gating is preserved via the existing `requireMasterAuth`
  call at the top of the handler.

## Audit log entry shape

Each genuine UPDATE produces exactly one `oauth_audit_log` row with:

| Field                  | Value                                                                          |
|------------------------|--------------------------------------------------------------------------------|
| `eventType`            | `"seed_upsert"`                                                                 |
| `actorTokenHash`       | `sha256Hex(callerToken)` (raw token never persisted)                            |
| `targetProfileId`      | catalog `profileId` (matches `existing.profileId` since no rename happens here) |
| `previousState`        | `{profileId, fromAllowList, namespaceReadPrefixes, namespaceWritePrefixes}` snapshot of the persisted row before the patch |
| `newState`             | same shape snapshot of the catalog seed                                         |
| `reason`               | `"seedDefaultProfiles upsert — catalog drift patched (S3.4 B4)"`                |
| `cascadeRevokedCount`  | `0`                                                                             |
| `clientsRetargeted`    | `0`                                                                             |
| `createdAt`            | `Date.now()` at patch time                                                       |

T6b confirms the no-op idempotent path writes NO audit row.

## Preserve operator-created profiles — rationale

T4 verifies that two non-catalog rows survive a seed run:

1. `operator-custom-tenant-x` — a hand-crafted scope profile created by an
   operator for a tenant outside the canonical catalog.
2. `<client-org>` — the post-D9 rename of `nadia-<client-org>` introduced by the
   `patch_nadia_iris_rh_scope` migration. After that migration ran, the
   row's `profileId` is `<client-org>`, not `nadia-<client-org>`. The catalog still
   carries `nadia-<client-org>` (post-Day-88 corrected prefixes). The upsert
   path treats them as distinct profileIds: `<client-org>` is "not in catalog"
   and is preserved, while `nadia-<client-org>` is inserted fresh if absent or
   patched if present.

The seed mutation has **no delete branch**. Operator-created profiles can
only be removed via an explicit admin path (out of scope for this sprint).

## Migration precedent obsoleted

`convex/migrations/patch_nadia_iris_rh_scope.ts` was created Day 90 to
remediate the `global` leak in the `nadia-<client-org>` row by hand-patching
the persisted state. The migration carries a header warning:

> MANUAL INVOCATION REQUIRED post-deploy — DO NOT auto-run

With S3.4 B4 in place, that pattern is obsolete for catalog-only drift
fixes. The next time a catalog seed needs editing, the change goes into
`convex/oauth.ts` defaults and propagates on the next deploy via
`seedDefaultProfiles` upsert, with a full forensic trail in
`oauth_audit_log`. The bespoke migration file is left in place for now;
its decommission is a separate task.
