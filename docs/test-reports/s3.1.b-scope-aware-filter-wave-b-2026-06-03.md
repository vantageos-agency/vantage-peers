## Friction observed

1. **Brief 4th-tool gap — `get_briefing_note` does not exist.** The brief
   listed `get_briefing_note` as Wave B tool #2 ("search by name — may be
   near 3063"). Grep on `mcp-server/src/tools.ts` at HEAD returns only
   `create_briefing_note`, `update_briefing_note`, `list_briefing_notes`. No
   `get_*` for briefing notes is registered in the MCP server, nor any
   corresponding Convex query (`grep getBriefingNote convex/` returns
   nothing). Wave B's strict-scope mandate forbids creating new tools, so
   the brief was reduced to the 3 existing tools. Recommended remediation:
   add `get_briefing_note` registration + Convex query under Wave C
   (`k17fjd4dvp34k9q57t5e1qzrv187zz9n`), then ship its scope-aware variant
   inline.

2. **Vacuous-pass RED phase by construction.** Because Wave A already
   shipped `scopeFilterList` green (SHA `251d183`), slice tests against it
   cannot fail at the RED commit. The honest cost of a true-RED Wave B
   would have been one of:
   - temporarily reverting the helper to a stub (would break Wave A's 17
     tests during the RED commit);
   - introducing a handler-integration harness (~30 k token cost,
     duplicates oauth-d6-d7 plumbing).
   Following Wave A's own precedent (its U3/U4/G2 cases passed vacuously),
   neither path was justified. Documented honestly here so Eta review can
   weight the test-suite signal accordingly. The cross-tenant assertions
   (BN-T3/T4, MSG-T3/T4, PEER-T3/T4, all T5) remain on the suite as
   regression guards against any future helper change.

3. **Wave A's `tools.ts` pre-existing diagnostics.** Wave A noted the
   5500-line `tools.ts` carries 200+ pre-existing biome warnings (template
   literal preference, explicit `any`). Wave B's edits are 3 small slices
   (5-10 lines each) and introduce **no new** warnings; the 213-warning
   baseline is identical pre- and post-patch. Cleanup deferred to a
   dedicated pass.

4. **Profile filter happens before peers projection.** `list_peers`
   synthesises a `peers` array from raw `profiles` rows. Filtering on
   `profiles` (which carry `createdBy` + `namespace`) BEFORE the projection
   keeps the contract: cross-tenant profiles never reach the projection
   step, so leaked fields (e.g. `name`, `currentTask`) are impossible. The
   alternative — filtering on the projected `peers` array — would lose the
   `namespace` field (projection drops it) and silently break PEER-T4.

5. **Friction declared in commits** per the brief's discipline directive.
   RED commit `700aa63` body declares the 4th-tool gap + vacuous-pass
   acknowledgement. GREEN commit `3d9e85c` body restates them.
