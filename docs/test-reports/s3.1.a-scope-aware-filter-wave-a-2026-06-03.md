## Friction observed

1. **Helper file pre-existed as untracked stub.** `mcp-server/src/scope-filter.ts`
   was already present in the working tree from a prior planning session.
   Adopted as-is (matches the brief's contract exactly), no duplicate created.
   Brief constraint "IF helper already exists → use it, don't duplicate"
   satisfied.

2. **Brief's RED expectation overshot.** The brief listed U3, U4, G2 in the
   expected RED failures, but those assertions are `true` and the stub returns
   `true` — they pass vacuously. The 7 actual RED failures (U5, U7, M2-M5, G3)
   cover every cross-tenant deny path, which is the security-relevant surface.
   No code change needed; documented here for Wave B/C reviewers.

3. **Hono `/mcp` round-trip harness deferred.** The brief suggested driving
   `list_memories` / `get_memory` through `app.request("/mcp", ...)` with a
   mocked Convex client. Doing so requires bootstrapping the full MCP JSON-RPC
   envelope + `McpServer` + `registerTools` + cross-cutting guards (auth,
   namespace, content-size). That harness cost was estimated to exceed the
   Wave A ~80 k token envelope. Instead the M/G suites exercise the **exact
   post-Convex-query slice** the GREEN patch introduces. JSON-RPC envelope
   coverage already lives in `oauth-d6-d7.test.ts` T13.

4. **No Alice-named fixtures.** The brief said "reuse alpha/beta/gamma pattern
   from oauth-d6-d7". Done — alpha/beta/gamma identities populate the
   6-memory fixture. No `alice` identifier hardcoded; the framework is
   identity-agnostic.
