## Paging contract

| Constant                | Value      | Purpose                                                                                       |
| ----------------------- | ---------- | --------------------------------------------------------------------------------------------- |
| `DEFAULT_LIMIT`         | 50         | Default page size for cursor-paged callers (existing `?? 20` legacy defaults left untouched). |
| `MAX_LIMIT`             | 200        | Hard ceiling; `clampLimit` floors out-of-range input.                                         |
| `ENVELOPE_TARGET_BYTES` | 50,000     | Pre-MCP-envelope (60 KB) headroom for framing + UI markers.                                   |

### Helpers (mcp-server/src/paging.ts)

- `clampLimit(limit?: number | null): number`
  - `undefined` / `null` / non-finite → `DEFAULT_LIMIT`
  - Floors non-integer values (`Math.floor`)
  - Clamps to `[1, MAX_LIMIT]`
- `encodeCursor(payload) → string` — base64url(JSON(payload))
- `decodeCursor(token) → CursorPayload | null`
  - `undefined` / `""` → `null` (no-cursor sentinel)
  - Garbage input → typed `Error` matching `/invalid cursor/i`
- `enforceEnvelopeCap(rows, targetBytes?) → { items, isCapped }`
  - Halves the rows array until serialized JSON ≤ target
  - Always returns ≥ 1 row (single-huge-row floor)
- `buildPageResult({ rows, hasMore, nextCursor, isCapped? }) → PageResult`

### Cursor token payloads

Tokens are intentionally opaque to MCP clients. Two payload shapes today:

1. `{ createdBefore: number, lastId?: string }` — used for Convex queries
   without `paginate()` (tasks, briefingNotes). Forward cursor anchor is the
   last row's `_creationTime`. MCP layer wraps it; Convex backend filters
   `_creationTime < createdBefore`.
2. `{ backendCursor: string | null }` — used for Convex queries that natively
   support `paginationOpts` (memories). MCP layer forwards the backend cursor
   unchanged.

Token format may evolve as long as `encodeCursor` / `decodeCursor` stay paired.

## Backward compatibility

- Tools called without `cursor` + without explicit `limit` fall through to the
  pre-S3.3 B8 `?? 20` envelope-safe default — no observable behavior change.
- Existing `fields=lite|full` parameter untouched (paging is additive).
- Existing `v2.3.5` boundary tests still PASS (limit=undefined → undefined
  forwarded to backend auto-clamp path).
- Convex `createdBefore` arg is optional everywhere → existing callers that
  don't set it are unaffected.

## Envelope cap behavior

The legacy `capListResponseBytes` guard (60 KB ceiling, item-array truncation
with `_meta._truncated` envelope) is preserved. The new `enforceEnvelopeCap`
helper (50 KB target) is exposed for future per-tool migration but is not
applied to the 3 wired tools in this PR — they continue to rely on
`capListResponseBytes` so legacy clients observe the same truncation envelope
shape.
