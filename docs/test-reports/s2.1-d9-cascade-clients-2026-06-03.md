## Scope tested

Extension of `patchScopeProfileEmergency` in `convex/oauth.ts`:
- New step: when `rename` arg is set and differs from `profileId`, walk `oauth_clients.by_scopeProfile` index for the old name and patch each row to `scopeProfile = rename`.
- Step inserted BEFORE cascade revoke (so revoke covers both old and new name).
- Return shape extended: `clientsRetargeted: v.number()` (additive, backward-compatible).
- Audit log extended: `clientsRetargeted: v.optional(v.number())` persisted per invocation.

Schema additive change: `convex/schema.ts` `oauth_audit_log` table — `clientsRetargeted: v.optional(v.number())` added. Optional for backward compatibility with pre-S2.1 rows.

Unchanged: master token guard, reason guard, D4 enforcement, selective patch, rename of profileId field, cascade revoke logic, audit log structure (previousState/newState).

## Schema migration safety

Change: `convex/schema.ts` `oauth_audit_log` table — added `clientsRetargeted: v.optional(v.number())`.

- Additive only: new optional field on existing table.
- Pre-S2.1 rows lacking the field remain readable — Convex treats missing optional fields as `undefined`.
- No backfill required for existing rows (pre-S2.1 audit entries simply have `clientsRetargeted=undefined`, semantically equivalent to 0).
- No index change — `by_targetProfileId` and `by_createdAt` indexes unchanged.

**Schema migration safety: additive, zero-downtime, no backfill needed.**
