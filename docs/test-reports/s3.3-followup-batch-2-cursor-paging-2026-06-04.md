## Backward compatibility

- Each MCP handler keeps the legacy `?? 20` default at the convex.query call site, so callers that omit `limit` keep the pre-batch page size. Only when `limit` is explicitly provided does the new `clampLimit()` path apply (matches PR #635 + batch 1 contract).
- Each Convex `createdBefore` arg is `v.optional(v.number())`; pre-batch callers never pass it, so they get exactly the pre-batch return.
- For `githubRepoMapping:list` we added a `limit` arg that defaults to `50` server-side, replacing an unbounded `.collect()`. Existing callers that previously got the full table (typically ≤ a dozen rows in production) keep getting their full result unless they exceed 50 — a doctrine-aligned ceiling consistent with the rest of the fleet.
- `list_issues` retains its existing `{count, issues}` envelope shape; `nextCursor` is appended only when the page is full.
- `list_messages` preserves the `appendMarkerIfEnabled` "messages-feed" sidecar marker exactly as before; cursor logic wraps the primary text payload only.
- `nextCursor` is added to the envelope only when the returned page is full (rows ≥ requested limit). Callers that ignore `nextCursor` see no behavioral change.
