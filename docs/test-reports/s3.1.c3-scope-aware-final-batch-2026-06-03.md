### `soft_delete_memory` exempt rationale (intentional non-migration)

`soft_delete_memory` (tools.ts L710) **remains** behind `guardMasterOnly` by design and is the **only** tool in the fleet excluded from the scope-aware migration. Rationale:

- The mutation `memories:softDelete` accepts only a `memoryId` — no namespace / `createdBy` / scope context is carried in the call surface.
- Destructive operation: the cost of a wrong scope check is silent data loss across tenants.
- No per-resource RBAC on the underlying Convex mutation today — adding one is a backend doctrine change tracked separately (out of Wave C scope).

This is the **terminal** post-C3 inventory: **28 of 29** scope-applicable tools migrated = **96%** coverage. The remaining 1/29 is `soft_delete_memory`, excluded by design.

### Grep-derived inventory note (Eta doctrine candidate adopted)

Wave C0/C1/C2 used memory-derived inventories prepared by prior briefings. Eta's post-C2 review discovered 2 unmigrated tools (`list_errors`, `get_error`) that were absent from those briefings. Root cause: human-maintained inventories drift from source as new tools are added. Wave C3 introduces the corrective doctrine:

> **Every scope-aware migration phase MUST derive its authoritative tool inventory from `grep -n "guardMasterOnly" <source>` against the current HEAD, not from prior memory or briefing recall.**

Applied in C3 Phase 0: the grep returned exactly 9 call sites (1 helper definition L593, 1 exempt L710, 8 migration targets). Targets matched the brief's expected set 1-to-1 — no surprises, no improvisation.

**Special — `instantiate_template_into_mission` (write, pre-mutation guard):**

```ts
// Pre-mutation scope guard on target mission.
const targetMission = await convex.query("missions:get" as any, {
  missionId: missionId as any,
});
const filteredMission = scopeFilterGet(oauthCtx, targetMission as any);
if (filteredMission == null) {
  return mcpError("Mission not found or not accessible to current scope");
}

const result = await convex.mutation(
  "missionTemplates:instantiateTemplateIntoMission" as any,
  { /* ... */ },
);
```

The scope check fires **before** the instantiate mutation, so a cross-tenant call cannot leak task creation under a foreign mission. Test ITM-M1 asserts `mutationCalls` for `missionTemplates:instantiateTemplateIntoMission` is `false` AND `res.isError === true` — both held at GREEN.

## Scope-aware decision matrix

| caller scope | master `*` | tenant-A in-scope | tenant-A cross-tenant | legacy bearer (no ctx) |
|---|---|---|---|---|
| list_* tool | all rows | rows where `createdBy ∈ allowList` OR `namespace` starts with read-prefix | foreign rows dropped | all rows (pre-D3 compat) |
| get_* tool | row | row if same predicate | `null` (non-leaky 404) | row |
| `instantiate_template_into_mission` (write) | mutation runs | mutation runs if target mission visible | **mutation rejected with non-leaky 404** before any side-effect | mutation runs |

Read-path semantics identical to Waves A/B/C0/C1/C2. The single write addition extends the same predicate into a **pre-mutation gate** rather than a post-query row filter.
