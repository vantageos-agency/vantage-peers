## Eta REVIEW follow-up (PR #621, Day 91)

Eta verdict: **REVISE** — 1 MAJOR + 2 advisory. All addressed on top of `963399a`.

### F1 (MAJOR) — constant-time `client_secret` hash compare

- **Defect** `presentedHash !== client.clientSecretHash` at `mcp-server/server-http.ts:577-580` (authorization_code) and `:707-710` (refresh_token) used non-constant-time `!==`. Timing-oracle on confidential client authentication (RFC 6749 §6).
- **Fix** Ported the `timingSafeEqual` helper from `convex/oauth.ts:23-45` into `mcp-server/src/crypto.ts` — **identical algorithm** (TextEncoder → bytes, length-mismatch guarded by a dummy HMAC over equal-length buffers, equal-length path XOR-accumulates diff). Both call sites now call `await timingSafeEqual(presentedHash, client.clientSecretHash)`.
- **Tests** Added `F1 — timingSafeEqual` block in `mcp-server/test/oauth-d6-d7.test.ts` — 3 cases (equal sha256 hex → true, different same-length → false, different-length → false + empty/empty → true). T7 wrong-secret 401 path already covers the functional 401 assertion.

### F2 (advisory) — canonical D14 doc path

- Doc renamed (`git mv`) to Eta's path `docs/test-reports/s1.5-oauth-d6-d7-2026-06-03.md`. `mcp-server/test/RED-PHASE-EVIDENCE.md` now carries a top cross-link to this report.

### F3 (advisory) — DCR pre-existing clients backfill

- See PR #621 body section "F3 — DCR pre-existing clients backfill". DCR clients minted Day 88-90 already store `clientSecretHash` via `oauth:createClient` (verified `convex/oauth.ts`). The new `tokenEndpointAuthMethod` field defaults to `"client_secret_basic"` (secure default) when absent — backward compatible. Backfill to be scheduled as S2 task before prod merge.
