## Scope

Phase C0 is a **registration prerequisite** for Wave C. During Wave B (PR #625, main `28db616`), the tool `get_briefing_note` was discovered to be **absent** from `mcp-server/src/tools.ts` — only `create_briefing_note`, `update_briefing_note`, `list_briefing_notes`, and `delete_briefing_note` were registered. The Convex backend query `briefingNotes:get` exists (`convex/briefingNotes.ts` line 33). Wave C cannot apply scope-aware to a non-existent MCP tool, so Phase C0 ships **only** the registration + scope-aware wiring for this single tool. No other tool is modified.

- VP-only change (no VCRM equivalent → D5 ship-together-pair not applicable).
- Mirrors `get_memory` registration pattern from Wave A (`mcp-server/src/tools.ts` L731-L764).
- Uses `scopeFilterGet` from `mcp-server/src/scope-filter.ts` to collapse cross-tenant rows to a non-leaky "Briefing note not found" error.

## Scope-aware decision matrix (`get_briefing_note`)

| Caller | Row owner / namespace | Result |
|---|---|---|
| `oauthCtx === undefined` (legacy bearer) | any | row returned (back-compat) |
| `isMaster === true` | any | row returned (wildcard) |
| scoped, `row.createdBy ∈ fromAllowList` | any | row returned |
| scoped, `row.namespace === p` or `startsWith(p + "/")` for some `p ∈ namespaceReadPrefixes` | matching prefix | row returned |
| scoped, neither match | foreign | `null` → MCP error `"Briefing note not found: <id>"` (non-leaky) |
| any caller | backend returned `null` (absent) | `null` → same not-found error |

The non-leaky behaviour is intentional: an attacker who guesses a note ID outside their scope receives the same response as a guess at a non-existent ID. This eliminates the "absent vs filtered" oracle.
