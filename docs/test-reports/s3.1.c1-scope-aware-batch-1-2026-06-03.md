## RED → GREEN evidence

### RED — 21/35 FAIL

Test plan per tool: 5 tests (T1 master, T2 non-master in-scope, T3 legacy bearer, M1 cross-tenant, M2 own-tenant).

| Test class | Cardinality | Expected status at RED |
|---|---|---|
| T1 — master scope | 7 (one per tool) | PASS (guardMasterOnly is a no-op for master) |
| T3 — legacy bearer (`oauthCtx === undefined`) | 7 | PASS (no-op for undefined ctx) |
| T2 — non-master in-scope | 7 | **FAIL** (Forbidden envelope returned) |
| M1 — cross-tenant non-master | 7 | **FAIL** (Forbidden envelope returned) |
| M2 — own-tenant non-master | 7 | **FAIL** (Forbidden envelope returned) |

Total: 14 PASS + 21 FAIL = 35. RED failure surface is uniform: `mcpError("Forbidden: <toolName> requires master scope (current: <profile>).")` short-circuits the handler before any scope-filter can run, so the response carries `isError: true` and a `Forbidden:` body. The negative-path assertion `expect(isForbiddenResponse(res)).toBe(false)` therefore inverts at GREEN.

### GREEN — 35/35 PASS

At `1387f69`, each tool's handler:
1. Drops `const _scopeDenied = guardMasterOnly("<tool>");` + early-return.
2. Forwards the Convex result through `scopeFilterList` (for list_*) or `scopeFilterGet` (for get_*).
3. Renders the filtered slice via the same `capListResponseBytes` / `JSON.stringify` / `appendMarkerIfEnabled` pipeline (no envelope semantics changed).

Full mcp-server suite at GREEN: **102/102 PASS** (67 baseline carried from C0 SHA `c516b88` + 35 new C1 tests). Zero regression.

## Scope-aware decision matrix (mirror of Wave A/B/C0)

| Caller | `get_*` tool | `list_*` tool |
|---|---|---|
| Master (`isMaster=true`) | row returned as-is | all rows returned |
| Legacy bearer (`oauthCtx === undefined`) | row returned as-is | all rows returned |
| Non-master + row in scope | row returned | row kept in filtered list |
| Non-master + row out of scope | `null` (non-leaky 404) | row dropped silently |
| Non-master + backend returned `null` | `null` (404 shape preserved) | empty list |

"In scope" = `row.createdBy ∈ oauthCtx.fromAllowList` OR `row.namespace` matches one of `oauthCtx.namespaceReadPrefixes` (exact or `/` boundary).

## Notes on row shapes

`profiles` and `diary` rows do not natively carry `createdBy` / `namespace` columns (schema unchanged in this PR). For non-master callers without those fields populated, `scopeFilterGet` collapses to `null` — same non-leaky semantic as Wave B's `list_peers`. Adding namespace/createdBy stamping to those tables is out of scope for C1 and will be addressed in a later sprint when the cascade-clients D9 surface lands.

## Harness convention

Tests use the C0 lightweight `McpServer` mock to capture each registered handler, then invoke it directly with a fixture-returning mocked `ConvexHttpClient`. This avoids bootstrapping the full Hono `/mcp` JSON-RPC envelope while still exercising the exact post-Convex-query slice the GREEN patch introduces. See `mcp-server/test/scope-aware-filter-wave-c1.test.ts` § captureTools.
