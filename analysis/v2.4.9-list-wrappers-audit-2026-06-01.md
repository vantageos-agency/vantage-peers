| `recall` / `hybrid_search` / `text_search` | N/A — semantic search shape inherent | n/a              |

**Wrapper-layer behavior**: when the Convex query ignores `fields`, the MCP layer still validates the schema and forwards the param. The query returns its default shape. **No breakage** — degrades to "full" silently.

**Followup PR (separate, tracked as VP task)**: thread `fields` projection through the 17 Convex query handlers.

### Minor 2 — HIGH RISK 100→20 default reductions broadcast

Two wrappers had silent default reductions impacting downstream callers:

- `list_messages`: 100 → 20
- `list_components`: 100 → 20

**Mitigation**: callers expecting larger pages MUST opt back via explicit `limit=N` (max 200). Fleet broadcast sent on `broadcast` channel post-publish so every orchestrator's check-messages cycle surfaces the breaking-change note.

### Minor 3 — Schema-correctness elevation

Three wrappers shipped pre-v2.4.9 with `z.number().int().optional()` (no min/max bounds, no default):

- `search_components`
- `list_fix_patterns`
- `search_fix_patterns`

**Post-fix (already in v2.4.9)**: all three now use `z.number().int().min(1).max(200).optional()` with default 20. This is a correctness fix (rejects negative / non-integer / huge values at the schema layer). Elevated here in the addendum since it deserves visibility beyond the audit table line items — the pre-fix wrappers let malformed calls through; post-fix they reject with a clear validation error.
