An org slug is a reusable label: org A is renamed, org B takes the slug. Any read that selects or admits by that label, without an
ID comparison, serves B the rows A stamped. Already fixed on this main: #1619 (resolveAgentRef), #1622 (principal lookups), #1624 (orgRoster mappingOfAccessToken).

## Reading guide

- `S` notes marked **S-dep** are safe only while the label they receive is current. They take a label from the MCP transport claim
  (`verifiedOrg`, `seatOrgSlug`, `verifiedActor.orgSlug`, all derived from the token row's snapshot label). Root A-1 below makes that label current; the S-dep lines then need no change.
- Where a site is ID-gated only in the post-filter (`filterByOrgScope` / `taskRowFilter`, both `sameOrg`, which compares IDs only and never matches a label,
  `node_modules/@vantageos/cloud-identity/dist/org-by-id.js:37-41`), the slug index is classed S: it narrows candidates, the ID check decides.
  A row with no `clerkOrgId` is withheld by that check (availability, not a leak).
