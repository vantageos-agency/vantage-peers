### Security
- **fix(auth): `withOrgScope` no-identity default flips fail-open → fail-closed; 4 client-facing handlers scoped; MCP legacy bearer path (4) no longer leaves `oauthContext` unset — STEP, not the multi-tenant model's completion** — `convex/lib/auth.ts` `withOrgScope(ctx, opts?)`: absence of a Clerk identity previously resolved unconditionally to `isMaster=true, allowedOrchestrators=["*"]`. It now defaults to fail-closed (`isMaster=false, allowedOrchestrators=[], scopes=[]`) unless the call site explicitly opts in via `{ allowNoIdentityMaster: true }` — the opt-in exists because Convex has no reliable signal to distinguish an MCP-server call without a JWT from an anonymous caller. The 10 existing internal call sites that pass the opt-in (`convex/tasks.ts`, `convex/missions.ts`, `convex/dashboard.ts`, `convex/stats.ts`, `convex/briefingNotes.ts`, internal `convex/messages.ts` paths, `convex/memories.ts`) are unaffected. Four previously-unscoped client-facing handlers now call `withOrgScope`/`filterByOrgScope`: `convex/memories.ts` (`listMemories`, `getMemory`), `convex/messages.ts` (`listByChannel`), `convex/diary.ts` (`list`). On the MCP side, `mcp-server/src/auth.ts` path (4) (legacy `mcpTenants` bearer) previously left `oauthContext` unset, which made every `tools.ts` guard (`guardRead`/`guardWrite`/`guardMasterOnly`) and every `checkNamespaceRead`/`checkNamespaceWrite`/`checkFromAllowed` predicate treat the request as unscoped/allowed; it now sets a deny-by-default context (`scopeProfile: "legacy-tenant-generic"`, empty `fromAllowList`/`namespaceReadPrefixes`/`namespaceWritePrefixes`, `isMaster: false`). New coverage: `convex/__tests__/multiTenantIsolation.test.ts` (5 tests: `withOrgScope` no-identity fail-closed unit test + cross-tenant read denial for `memories.listMemories`, `memories.getMemory`, `messages.listByChannel`, `diary.list`). Full Convex suite **2384 passed / 12 skipped, exit 0**. **This closes one fail-open gap; it is not the completion of the multi-tenant model** — the full contract (each tenant reads/writes strictly its own data everywhere) remains the product direction reaffirmed by Laurent and is tracked/realigned separately by Pi. Open follow-ups, not resolved by this fix: (a) a non-MCP anonymous call site explicitly passing `allowNoIdentityMaster: true` still resolves to master; (b) the legacy-tenant (path 4) e2e test now falls under an empty scope by design and needs re-provisioning via the OAuth scoped-token path with explicit prefixes; (c) whether a `global` namespace prefix belongs in Alice's OAuth profile is undecided — TODO confirm intent with Laurent; (d) no real-network e2e against a live Clerk JWT has been run — isolation is proven at the `convex-test` harness level only. ## [2.3.0] — 2026-05-21

### Bug Fix — recall()/hybrid_search() returning [] for self-host with direct OpenAI key

**Root cause (self-host incident, 2026-05-18):** When a self-host operator placed
a direct OpenAI key (`sk-*`) into the `AI_GATEWAY_API_KEY` environment variable, the
embedding provider was routed to `https://ai-gateway.vercel.sh/v1` (the Vercel gateway
base URL). The gateway rejected the direct key with 401 → embeddings silently returned
empty vectors → `recall()` and `hybrid_search()` returned `[]` even after reindexing.
`text_search` (BM25) was unaffected because it does not call the embedding endpoint.

**Fix (`convex/lib/aiClient.ts`):**
- New `isDirectOpenAIKey(key: string): boolean` — detects `sk-*` prefix.
- New `resolveEmbeddingPath()` — explicit routing function with three outcomes:
  `openai-direct` (OPENAI_API_KEY or sk-* in AI_GATEWAY_API_KEY),
  `gateway` (non-sk-* AI_GATEWAY_API_KEY),
  `missing` (neither set).
- `getAITextEmbeddingProvider()` and `getEmbeddingModelName()` now delegate to
  `resolveEmbeddingPath()` — sk-* key in AI_GATEWAY_API_KEY routes to `api.openai.com/v1`
  with the bare model name `text-embedding-3-small` (not the `openai/` prefixed name).

**Backward compatibility:** existing Vercel AI Gateway keys (non-sk-* tokens) and
`OPENAI_API_KEY` behavior are fully preserved.

**Tests:** 19 unit tests in `convex/lib/aiClient.test.ts` covering all routing branches
including the sk-*-in-AI_GATEWAY_API_KEY regression case (direct path).

**Remediation for affected self-host clients:** see
`docs/self-host/recall-empty-troubleshooting.md` — set `OPENAI_API_KEY`, redeploy,
run reindex mutation.

**References:** self-host support ticket 2026-05-18 , 2026-05-20 reindex PR #483,
