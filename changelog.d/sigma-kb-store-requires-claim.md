section: Security
---
- **VantagePeers Cloud `store_document_chunked` ingests only a blob your organisation claimed; the first org to present a storageId no longer owns it.** Before, `kb:storeDocumentChunked` bound an unclaimed storageId to whichever org ingested it first (trust on first use), so a leaked storageId could be ingested by the wrong tenant. Now it asserts the claim written by `claim_upload` (`generate_upload_url` with `sha256` -> POST -> `claim_upload` -> `store_document_chunked`), keyed on the verified org, and an unclaimed storageId is refused with the same `AUTH_STORAGE_NOT_OWNED` as a foreign one. A binding already written by the old path is honoured for the same org only. No MCP contract change (new internal mutation `kbMutations:assertStorageClaimedBy`; tool descriptions updated). A `generate_upload_url` call without `sha256` now yields a URL whose blob cannot be ingested. Evidence: `convex/__tests__/kbStoreRequiresClaim.test.ts` 6/6, 2/6 red on 93d814ae.
