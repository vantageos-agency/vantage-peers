- **A task may reference only an existing mission of its own tenant.** `tasks:create` and `tasks:update` refuse a foreign (or fleet) `missionId` for an organisation caller with the typed refusal `MISSION_FOREIGN_TENANT`, and a nonexistent `missionId` for every caller (the master included) with `MISSION_NOT_FOUND`, through one shared predicate (`convex/lib/missionTenant.ts`, the R-52 `sameTenantStamp` rule); nothing is written. The fleet master acting for no organisation keeps its reach over an existing mission. The mission auto-complete all-done scan counts only the mission's own tenant's tasks, so a foreign task row can no longer keep another organisation's mission open. New read-only internal query `migrations/taskMissionTenantLinks:count` returns counts only (per org slug: tasks pointing to a foreign mission or a nonexistent one; totals examined; paged, `truncated` + `nextCursor`), never an id or row content. No change to any argument or return shape of a public door: no contract bump. Task k175x770r9f6h01xt0wg0hdd798hf8m4.
