- **Every tool description states the result it really returns, envelope first.** The `Returns { ... }` clause of all 93 tools now names exactly the top-level properties of the tool's output schema (the envelope: `items`, `truncated`, `nextCursor`, `found`, ...), and then the fields of the rows those properties hold (`items[{ ... }]`, `item { ... }`), every required one; the single-row reads `get_memory`, `get_episode`, `get_briefing_note` and `get_task` name their fields instead of "the row as JSON", and a read that finds nothing is described as the error result it is. A new test (`mcp-server/test/returns-envelope.test.ts`) compares every clause with the schema served in `tools/list`. Also: `correct_task_segment.reason` carries its rule (at least 12 characters other than spaces, the door's own) in the input schema, so it is refused before the backend and the description no longer restates it; `export_okf_bundle.urlTtl` says the URL lasts one hour when it is omitted; `soft_delete_document` says what `docId` and `markedCount` mean (the count covers the call's first batch of 200 chunks); `list_peers` is titled "List peer agents and their status".
