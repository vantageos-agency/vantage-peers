section: Security
---
- **An agent can be bound to a human owner, and the owner is proven on every resolution (Cloud, `@vantageos/cloud-identity` 0.21.0).** `agents.ownerPersonId`, `agent_credentials.ownerPersonId` and `oauth_access_tokens.ownerPersonId` are new optional fields (expand-only). A credential or seat token copies the owner from the AGENT ROW at mint, never from an argument. `resolveAgentCredential` and `oauth:getAccessTokenByHash` resolve the agent through the package's `resolveCallerFromAgentCredential`: the organisation by its permanent ID, the agent read by ID, and the owner proven against the agent's stored owner (`agent-owner-mismatch`) and the owner's active membership of the agent's organisation (`agent-owner-not-member`). The lookups are plain indexed reads by ID (`agentCallerDeps`, `convex/lib/actingPrincipal.ts`); the people are rows of the new `persons` table. A credential or token whose owner the package refuses is not served; an agent with no owner resolves as before. `agents:setAgentOwner` and `persons:setPerson` are internal, operator-run functions (no new public registration); `migrations/agentOwnerRows:backfillAgentOwnerIds` copies the owner onto existing credential and token rows (dry run by default, idempotent). The MCP server forwards the proven owner on the actor and the seat; it decides nothing. Deploy order: run `backfillAgentOwnerIds` (dry run first) after binding owners; agent rows and credential rows without a permanent org ID (`backfill_org_clerk_id`) no longer resolve.
