- **VantagePeers Cloud: an agent (seat) can now erase what it wrote, and every tenant table has a written erase decision.** `erase_memory` refused every seat ("for a signed-in person") although clients act through agents and agents author most memories. One rule now covers eleven tables (memories, messages, missions, tasks, recurringTasks, briefingNotes, diary, debateRooms, issues, businessUnits, debateTemplates): an organisation admin erases any row of its organisation; an author erases the rows it wrote, a person by verified subject (`user:<subject>`), an agent by the agents-row ID the transport verified (`createdById`, `fromId`), never a typed name; another organisation and a same-organisation non-author are refused `RBAC_DENIED`, row unchanged. The erase is real: the row and the rows that exist only for it (receipts, debate turns, briefing chunks) are deleted and a memory's search entry is purged (`ragSync:removeRagEntry`, every version of the entry). New MCP tool `erase_row` (`table` enum = the covered list, one shared Convex door `erase:eraseRow`, one mechanism in `convex/lib/eraseRow.ts`; the internal `erase:eraseRowFleet` is the operator's reach); `erase_memory` now serves a seat through `memories:redactMemoryContentAsAgent`. `createdById` is now stored on memories (store_memory, store_episode, OKF import) and diary entries (`diary:write` takes `verifiedActor`); rows written before it, or by a seat that presented no agent proof, are erasable by an organisation admin only (no backfill). The other 22 tenant tables are skipped with a written reason (credentials, identity, system logs, derived rows); `convex/__tests__/tenantEraseCoverage.test.ts` derives the table list from the schema and fails when a tenant table is neither covered nor skipped. Backend contract 18 -> 19: deploy Convex first, then the MCP.
