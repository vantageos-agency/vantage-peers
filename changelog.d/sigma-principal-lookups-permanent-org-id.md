section: Security
---
- **The principal lookups hand the organisation's permanent ID to the identity package, not its slug (VantagePeers Cloud).** `principalLookups` and `principalLookupsOverAgents` answered `orgId: agents.orgSlug`, a renamable label, so after an organisation released a slug and another took it, the new holder passed the previous holder's agent ID to `tasks:create`/`tasks:update` (`assignedToAgentId`), `mandates:create` (`fulfilledByAgentId`), `messages:sendMessage` (`fromAgentId`, recipients) and the roster, profile, diary, directory and `verifiedActor` checks, and was judged "stamped with the org the credential names". The lookups now answer the row's `clerkOrgId` (null when absent, which the package refuses), the organisation reads are keyed by that ID, and every consumer compares permanent IDs: a label held by a door is converted once at its edge to the ID its mapping row stores now (absent or ambiguous fails closed), and a door that holds the verified ID passes it. An agent row with no `clerkOrgId` is refused, never matched by slug; a renamed organisation's caller is now admitted for its own agents under its new slug. Convex only, no public argument or return change, no schema change; `listedAgentsOfOrg` and `rosterOf` now take the org ID. Pinned by `convex/__tests__/principalLookupsSlugTakeover.test.ts`. Prod must be counted for `agent_credentials` rows with no `clerkOrgId` (resolved by their label's current ID meanwhile) before deploy.
