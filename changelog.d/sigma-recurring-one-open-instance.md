- **A recurring routine no longer stacks one task per day while its previous instance is still open.** `recurringTasks:processDueTasks` now looks for the previous instance (`lastTaskId`, or for legacy rows a bounded same-title, same-org lookup, read through `tasks.by_assigneeId_status_updatedAt` by the assignee agent ID when the schedule carries `assignedToId`, and through the tenant's open bucket `by_orgId_status` when it does not, so no assignee name is ever compared: there a same-title open task held by another assignee of the org also counts as open and the tick skips) before inserting. If it is open (todo, in_progress, review, blocked) the tick creates nothing, advances `nextRunAt` as a normal run would, and records the skip on the schedule (`skippedRuns`, `lastSkippedAt`, `lastSkipReason`, all new optional fields; `lastTaskId` too). A lookup that hits its bound (1000 per status bucket), or one that exhausts the shared per-transaction scan budget (`PROCESS_DUE_SCAN_BUDGET`, 4000 rows), counts as unknown and skips with a recorded reason rather than creating. Design: skip, not re-date the open task. `get_recurring_task` / `list_recurring_tasks` descriptions name the new fields. Tests: `convex/__tests__/recurringTasks.oneOpenInstance.test.ts`.
