- **Result shape: the four reads that may find nothing now return `structuredContent` `{ found, item }` / `{ found: false, id }`.** `get_profile`, `get_mission`, `get_mission_template` and `get_diary` declare an `outputSchema`; a client that reads structured content gets `{ found: true, item }` for a row and `{ found: false, id }` (the orchestratorId, missionId, template name or `<orchestrator>/<date>` asked for) where it used to read a bare JSON `null`. Their text content is unchanged (the row as JSON, or `null`). The MCP App document of `get_diary` reads `item` from it, and renders "No results" for `found: false`.
- **`check_messages` and the six Knowledge Base / OKF tools return `structuredContent` with a described `outputSchema`.** `check_messages` gives `{ messages, truncated, nextSince, stuckInProgress, peersStuckOnYou }`, the values its text is written from, and its text is unchanged. `generate_upload_url` gives `{ uploadUrl, ticket, expiresAt?, note? }` (its two text items as one object); `claim_upload`, `store_document_chunked`, `soft_delete_document`, `export_okf_bundle` and `import_okf_bundle` give their result object. 82 tools now declare an output schema.
