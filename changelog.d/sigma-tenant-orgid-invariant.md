- **VantagePeers Cloud ops: read-only count of the org ID over every tenant-scoped table, derived from the schema.** `migrations/tenantOrgIdInvariant:count` reads `convex/schema.ts` at run time (a table is tenant-scoped when it declares a string `clerkOrgId`/`tenantOrgId` and/or a string `clerkOrgSlug`/`orgSlug`/`orgId`/`tenantId`; the rule is in the module header), so a new tenant table is counted without editing a list, and it refuses when the derived set is empty. Per table it returns `{table, slugField, idField, examined, stamped, slugOnly, unstamped, resolvable, done, cursor}`: counts only, no id, no slug. A slug-only row matches no tenant under `sameOrg`; `resolvable` is how many of them the guarded resolver of `backfill_org_clerk_id` would fill. It writes nothing and replaces the typed-list count proposed on the same branch. `.claude/scripts/convex-prod.allow` gains `run migrations/tenantOrgIdInvariant:count` and `run migrations/backfill_org_clerk_id:run`.
