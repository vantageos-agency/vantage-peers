- **Prod-deploy guard: authorisation is verified by an Ed25519 signature, offline.** `enforce-pi-authorization-before-prod-deploy.py` decided by calling the identity provider over the network and then reading the token task from Convex; a bot filter in front of the provider (HTTP 403, code 1010) once stopped every deploy of the fleet. A command that carries `# pi-auth-payload: ... # pi-auth-sig: ...` beside `# pi-authorized: k<id>` is now judged by verifying that signature locally against `.claude/config/deploy-authority-pubkeys.json` (issuer to a list of keys, so rotation works). The payload binds task, commit floor, target deployment, orchestrator and issued-at; the window is measured on the signed issued-at; a field that does not match what the command does blocks and names the field. Three exits stay three: allow, block (each reason named), refuse to judge (malformed or absent key config, broken verifier). The verifier is `cryptography` when importable and a bundled RFC 8032 implementation otherwise (`.claude/hooks/_lib/ed25519_offline.py`); the audit line names which one ran. Signing tool: `.claude/scripts/sign-deploy-authorization.py` (key only from `DEPLOY_AUTHORITY_SIGNING_KEY_<ISSUER>` injected by `infisical run`). Runbook: `runbooks/prod-deploy-offline-signature.md`. Pinned by the `offline_signature` poles in `.claude/hooks/tests/test_enforce_pi_authorization_before_prod_deploy.py`, run on the real hook with the network removed.
