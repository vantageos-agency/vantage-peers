- **Cloud, prod data: a briefing note at Convex's 1 MiB document limit can now take its organisation stamp, with its body unchanged (tasks k17d10f1j2k2crgx9cw9bvw1vs8h7fda, k173kn4xsqmw3s5zx6522weqk18fttvs).** Measured on production: 30 briefing notes sit at 1,048,486..1,048,576 bytes, and the platform refuses the 90-byte org stamp ("Value is too large (1.00 MiB > maximum size 1 MiB)"). Pi's ruling: the BODY leaves the row, the row keeps a reference and the stamp, every read returns the body, nothing is trimmed. Added: optional `briefingNotes.bodyRef` ({chunks, bytes, sha256}) and table `briefingNoteBodyChunks` (index `by_note_idx`); body chunks are rows because the briefingNotes reads are queries and a query cannot read a file-storage blob. `migrations/offloadNoteBody:offloadOne {id, dryRun?}` (internal, dry run by default) writes the chunks, re-reads them, refuses with `BODY_HASH_MISMATCH` unless the sha256 of the body is identical before and after, replaces `content` by a 4000-character preview, sets `bodyRef` and stamps the organisation with the same resolver as `backfill_org_stamp`. `get` returns the whole body. `list` and `searchBriefingNotesByKeyword` (full) hydrate within a 4 MiB body budget; a note that does not fit keeps its preview and is MARKED `contentTruncated: true` (with `bodyRef`), never passed off as the content. Full-text search of an offloaded note covers its preview only (the first 4000 characters), so a keyword deeper in the body no longer finds it. The OKF export marks an offloaded row and the export actions read each body whole; the OKF import dedup compares an offloaded note by `bodyRef.sha256`. `briefingNotes:update` with new `content` drops the stale body; `deleteBriefingNote` deletes the chunks. Two internal operator doors: `agents:registerAgentInOrgById {clerkOrgId, name}` (org by permanent ID, active mapping required, name uniqueness enforced, no roster touched) and `briefingNotes:deleteTestNoteById {id}` (refuses unless the title starts with `[TEST]`; hard delete, `briefingNotes` has no soft-delete field). No MCP change: the MCP reads the hydrated query results. Tests: `convex/__tests__/briefingNoteBodyOffload.test.ts` (34).
