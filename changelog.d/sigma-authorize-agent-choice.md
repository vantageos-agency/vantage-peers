- **VantagePeers Cloud: the OAuth consent screen now lets a person choose the agent their connector acts as.** After the organisation choice, the screen lists the agents of that organisation that designate the person or nobody (by ID, name shown; never a seat-owned, inactive, service or other person's agent). Approve binds the chosen agent in the same Convex transaction that issues the code (`oauth:putPersonCodeWithAgent`), so a token minted from the code resolves that agent without an operator write; an agent bound to someone else in between is refused and no code is issued. An organisation admin may also create an agent by name (unique per organisation, `AGENT_NAME_TAKEN` otherwise); a member with nothing listed is told to ask their admin and can still approve as a person. Same flow for every client. Re-binding an agent from one person to another stays the operator door `agents:setPersonalAgentOf`. Two new Convex functions called by the MCP (`oauth:putPersonCodeWithAgent`, `oauth:listPersonalAgentChoices`), no argument change: Convex first, then the MCP. Tests: `mcp-server/test/authorize-agent-choice.test.ts`.
