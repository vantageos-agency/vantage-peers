section: Security
---
- **A person connection (ChatGPT, Claude, Grok through `/authorize` and consent) now gets a refresh token and no longer dies at access-token expiry (VantagePeers Cloud).** `/token` returns `refresh_token` on the `authorization_code` exchange and the `refresh_token` grant returns a new access token and a new refresh token for the SAME agent (`oauth:createAccessToken` gains the optional `personRefresh` argument and writes the refresh row in the same transaction; `oauth:rotateRefreshToken` takes a person branch (its seat-profile arguments become optional, required for a seat row); additive optional fields and three indexes on `oauth_refresh_tokens`; backend contract version 8 to 9). Authority is re-resolved live at every refresh: the member (by permanent org ID), the organisation mapping, the stamped agent (active, designating the person) and its place on `allowedAgentIds`; never a scope profile or a copy of the old token. Every use rotates the token, and reuse of a spent one is refused and revokes the whole family. A member removal, an agent deactivation (`agents:deactivateAgent`) or an organisation revocation (`oauth:revokePersonRefreshTokens`) revokes the refresh tokens at once. A family cannot be refreshed past `PERSON_REFRESH_FAMILY_MAX_DAYS` days from its first issuance (default 90 when unset or unreadable, never "no limit"). The agent never changes on refresh, scopes never exceed the consented ones, `offline_access` confers nothing, and refresh tokens are stored hashed only. Rollout: Convex first with a read-back, then the MCP (the boot check refuses a backend below contract 9). Pinned by `convex/__tests__/personRefreshTokens.test.ts` and `mcp-server/test/person-refresh-token.test.ts`; `oauth-end-to-end-by-identity.test.ts` no longer pins the refresh token absent.
