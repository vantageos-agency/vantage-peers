- **The inbox reader keys on `recipientId` only; the name fallback is deleted (R-53, module M6, VantagePeers Cloud).** An agent reader (`verifiedActor`, or a `verifiedOrg` name that resolves to an agents row) owns a receipt only when `receipt.recipientId` is its verified agent ID. A receipt addressed by NAME (no `recipientId`) was delivered to the same-named agent of the receipt's tenant, although the name is shared by agents of different organisations; it is now delivered to nobody and REPORTED by the new internal query `receiptRecipientIdAudit:unaddressedUnreadPage` (receipt ID, tenant, name; an empty list is a real empty success). The agent reader's name probes (`by_recipient_unread`, `by_tenant_recipient_unread`, the roster spellings, the legacy filter) are removed, and its `recipient` narrowing is compared by ID. Fleet, member, org-name and operator-admin readers hold no agent ID and stay name-keyed inside their own tenants. **Deploy order (two steps, one PR):** step 1, prod `migrations/backfill_actor_ids:run {"table":"messageReceipts"}` (dry run, then `"dryRun":false`, until `nextTable` is null) with a read-back dry run whose `toFill` is 0; step 2, deploy this reader. Deploying the reader first leaves every unstamped receipt unread until the backfill runs (reported, not lost). Tests: `convex/__tests__/inboxById.test.ts`; `inboxByAgentId.test.ts` and `inboxOldMcpWire.test.ts` updated to the ID-only contract.
