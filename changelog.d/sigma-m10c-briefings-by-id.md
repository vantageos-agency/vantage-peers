section: Security
---
- **Briefing notes are read and written by ID scope (module M10c).** `briefingNotes:list` and `searchBriefingNotesByKeyword` select a member's notes by the org's permanent ID (`by_orgId_clerk_id`, `by_orgId_topic_clerk_id`, and `clerkOrgId` as a search filter field), so an org that took a freed slug reads none of the notes of the org that held it; `get` takes `verifiedOrg` and `get_briefing_note` forwards it. The author is the verified caller: `create`, `update` and `deleteBriefingNote` accept `agentCredentialSecret` / `verifiedActor` (the MCP forwards `verifiedActor` on `create` and `update`), store `createdById`, and compare agent IDs, so a same-named agent of another org, or a member typing the author's name, edits nothing (`AGENT_CREDENTIAL_REQUIRED`, `actor-not-an-agent-of-org`, `not-creator`). Participants are matched by ID (`participantIds`, `briefingNoteParticipants.participantId`, index `by_participantId_note`); labels stay for display. The `createdBefore` cursor is now part of the index range (page two of `list` was empty). New optional columns only; rows written before carry no IDs and are resolved from their labels in their own org. Evidence: `convex/__tests__/briefingNotesById.test.ts` 17/17 (13 red on the previous head), `convex/__tests__/audit/briefingNotes.twoPoles.test.ts` 6/6.
