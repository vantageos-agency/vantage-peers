- **VantagePeers Cloud and Self-host: an organisation that adopted explicit review routing can no longer assign a task against its own route.** `create_task` takes an optional `repo` (`owner/name`, checked and not stored). For an adopted org, a task naming a repo routed to another owner is refused naming that owner (`RBAC_DENIED`, reason `repo-routed-to-other-owner`); a repo absent from the org's table is refused with "declare it first" (`repo-not-declared`, `add_repo_mapping`); a `[Review]` task, or one tagged `review`, naming a reviewer other than the routed one (or its fallback) is refused (`reviewer-not-routed`, `repo-has-no-reviewer`; the row's declared `fallbackReviewer`, the stop-over reviewer, is accepted as well as the primary); the webhook's `createOrUpdateReviewTask` `assignedTo` override is held to the same rule. An org that has not adopted routing is unchanged. Backend contract version 30 to 31: deploy Convex first, the MCP last. The prod guard allow-list gains `run clientOrgMapping:setReviewRoutingAdopted`, so the operator can adopt an org after this ships; without adoption none of these refusals fire.
