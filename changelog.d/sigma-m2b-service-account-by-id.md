section: Changed

- **VantagePeers Cloud: the fleet service account is stored data, not an environment value (M2 part 2).** `withOrgScope` and the `oauth` `requireServiceAccount` gate no longer compare the caller's subject to `CLERK_SERVICE_ACCOUNT_USER_ID`. A subject is the service account only when an `agents` row of `kind: "service"` carries it as `authSubject` AND the operator org's `client_org_mapping` row names that row in the new `serviceAccountAgentId` column; `@vantageos/cloud-identity` (`resolveActingPrincipal`) builds and judges the `fleet` principal from those ID-keyed rows. An absent column, absent or inactive row, wrong kind, or a subject the row does not carry is refused `RBAC_DENIED`; there is no fallback to the env var. Schema (expand only): `agents.kind`, `agents.authSubject` (+ index `by_auth_subject`), `client_org_mapping.serviceAccountAgentId`. Deploy order: schema, then run `npx convex run migrations/linkServiceAccountAgent:linkServiceAccountAgent` (dry run; it prints the pre-state), then `'{"dryRun":false}'`, THEN deploy the code that stops reading the env var, so the fleet is never locked out. Evidence: `convex/__tests__/serviceAccountById.test.ts` 16/16, `convex/__tests__/linkServiceAccountAgent.test.ts` 6/6.
