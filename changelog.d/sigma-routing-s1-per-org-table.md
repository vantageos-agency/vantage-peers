- **Per-org review routing: an absent repository is an explicit state, never a fallback (Cloud).** `githubRepoMapping:getRoute` answers the caller's own org with `routed` (owner, reviewer, optional fallback), `unreviewed` (owner only) or `absent`; another org's row is answered as `absent` with none of its content, and a caller with no credential is raised at (`RBAC_DENIED`). An org adopts explicit routing as data (the org's permanent clerkOrgId listed under the `taskClosureConfig` key `reviewRoutingAdoptedOrgs`, never in the mapping's `scopes`, which is copied into callers' authority; set by the internal `clientOrgMapping:setReviewRoutingAdopted`): for its repositories `resolveReviewer` and `acceptedReviewers` never read the fleet defaults (an absent row or a row with no reviewer is `REVIEWER_UNRESOLVED`), and `githubRepoMapping:add` refuses a mapping that names no reviewer (`REVIEWER_REQUIRED`). Adoption survives every change of a mapping's `clerkOrgId` (`setClerkOrgId` stamping or replacing an id, and `migrations/restamp_clerk_ids` on `client_org_mapping`): one writer re-keys the org's entry in the same mutation, and a repo row whose stamped id lags is resolved by its label. A non-adopted org is unchanged. The internal migration `migrations/stampFleetRepoMappings` (dry-run by default, idempotent, with `revert`) stamps the operator org on the fleet's unstamped routing rows. Tests: `convex/__tests__/routingPerOrg.test.ts`.
