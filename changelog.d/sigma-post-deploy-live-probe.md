- **VantagePeers Cloud ops: a post-deploy live probe checks real seat connections after every rollout.** `scripts/post-deploy-probe.mjs` connects to the deployed MCP as the two dedicated probe seats (`probe-tenant-a`, `probe-tenant-b`), derives their agent ids from `whoami`, and checks that each seat can write and read back its own `orchestrator/<agent id>` and `project/<slug>` and is refused (typed code) when it aims the same calls, a send, and a read of the other org's rows at the other org. Exit 0 PASS, 1 FAIL (names org, call, response), 2 COULD-NOT-JUDGE (unreadable credential, unreachable MCP, whoami failure; never a pass). Optional second probe agent per org: the in-org send is delivered and read back from the recipient inbox; without the second credential the probe falls back to the single-agent check and says so (NOTE line and summary). Bipolar test `scripts/__tests__/test-post-deploy-probe.sh` (24 cases against a local stub, each check mutation-tested: exact-content read-back, typed refusals on cross-org write, send and read, in-org delivery read back by a second probe agent). The rollout runbook now ends with this step and requires its output in the completion note.
