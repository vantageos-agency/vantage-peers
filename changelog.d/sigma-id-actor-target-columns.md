- **Actors and targets are now stored by ID, not only by name (expand phase, R-53).** New optional columns: `tasks.createdById`, `assignedToId`, `lastAssignedToId`, `cancelledById`, `reviewArtifactAttachedById`, `messages.fromId`, `messageReceipts.recipientId`, with indexes `tasks.by_assigneeId_status`, `messages.by_fromId`, `messageReceipts.by_recipientId_unread`. The ID is the `agents` row `_id` for an agent and the stable `user:<subject>` principal for a person. The name columns stay the labels and the authorisation compare; the door lanes move to the IDs later. New writes (`tasks.create`, `tasks.update` reassignment, the webhook/recurring/template/OKF task inserts, `messages.sendMessage`, the unblock notification) stamp the IDs from the verified org's own agents row, never from a typed name alone. `migrations/backfill_actor_ids:run` fills existing rows (paged, dry run by default, inventory first): a name resolves once within the row's own org (unstamped rows in the operator org); an unknown or ambiguous name stays unset and is listed by row ID; another org's same-named agent is never matched (the clio / iris-rh case). Run it after `backfill_org_stamp`. `backfillActorIds.test.ts` 10 tests, RED before (0 of 10 load without the migration; 3 write-path poles fail without the stamping). Name-only actor columns on other tables are listed for follow-up lanes: missions, briefingNotes, diary, recurringTasks, memories, mandates, issues, businessUnits and others.
