section: Fixed

- **OAuth discovery for VantagePeers Cloud names the `/mcp` URL clients configure, says which client types it accepts, carries `iss`, and no longer throttles a shared egress IP as one client.** Protected Resource Metadata (RFC 9728) now returns `resource: <base>/mcp` (was the bare origin) and is served at both `/.well-known/oauth-protected-resource` and `/.well-known/oauth-protected-resource/mcp`; the 401 from `/mcp` points `resource_metadata` at the `/mcp` variant. Authorization server metadata (RFC 8414) adds `none` to `token_endpoint_auth_methods_supported` (DCR already registered public clients and `/token` already honoured PKCE-only) and `authorization_response_iss_parameter_supported: true`; `/authorize` appends `iss` to its redirect (RFC 9207). Client ID Metadata Documents are NOT advertised, because `/authorize` and `/token` do not resolve a URL-shaped `client_id`. `POST /register` rate limit: was 5/min per IP; now 10/min per (IP, sha256 of client_name + sorted redirect_uris) and 60/min per IP as the abuse ceiling, with expired buckets swept past 10 000 keys. The rate-limit IP is now the one the trusted edge observed (`clientIpForRateLimit`): `x-real-ip` (set by the Railway edge), else the RIGHTMOST `x-forwarded-for` entry, else one shared `unknown` bucket. It used to be the first `x-forwarded-for` entry, which the client controls, so rotating that entry bypassed the per-IP ceiling. Tests: `mcp-server/test/oauth-discovery-quick.test.ts` (16 poles; 10 RED on d440b95, 3 more RED under the first-entry mutant); `mcp-server/test/sigma-url-fallback-regression.test.ts` header assertion moved to the `/mcp` variant. Docs: `mcp-server/README.md`, `docs/cloud/onboarding-customer.md` (connector URL ends in `/mcp`).
