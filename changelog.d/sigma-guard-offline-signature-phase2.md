- **Prod-deploy guard, phase 2: the network authorisation path is deleted, and the trust root can no longer be chosen by the process environment.** `enforce-pi-authorization-before-prod-deploy.py` no longer holds `guard_identity`, `_post_json`, `read_task` or `validate_task`; a bare `# pi-authorized: k<id>` is refused as `offline-signature-required`, and only a verified offline signature allows. `VP_GUARD_PUBKEYS_FILE` is ignored in every run (the audit line records `trust_root_env_override: ignored`); the public keys come from `.claude/config/deploy-authority-pubkeys.json`, and only a test driver can hand the hook another path, as a Python global under its own temp root. The signed `orchestrator` is always compared with the station's declared identity (`PI_AUTH_ORCHESTRATOR`, else `VP_ORCHESTRATOR`); a station that declares none refuses to judge instead of skipping the check, so such a station must set one before it can deploy. The runbook now states that a signed authorisation cannot be withdrawn inside its 120-minute window and that rotating the key out of the config is the remedy. Task k176yhdtn9kbht75skevmhgwn18fb6wp.
