- **VantagePeers Cloud and Self-host: the `ui://vp/v1/memory-quote` resource and `list_blocked_on_me` state the calling agent's verified ID on the door call (task k1740ydgqb7bxwnftrfyskx1ch8jwtgg, S-28).** The memory-quote resource reads `memories:listMemories` through the resource fetcher, which carried the organisation claim and never the agent ID, so a seat reading `orchestrator/<its own agent ID>` through the resource was served as an ordinary member of its organisation. It now forwards the agent ID the caller's verified context holds, the same claim, from the same source, that a tool call carries; a caller that resolved no agent ID, and a Clerk session, are sent what they were sent before. `list_blocked_on_me` states the same claim in its own call; the wrapped client already added it, so no answer changes. No caller's answer goes from a success to an error and no credential that works today is refused: the other twelve sites mcp-doctor reads on the MCP side are left as they are, each pinned per caller class by `mcp-server/test/s28-batch4-sites.test.ts`. Not breaking, so a patch release.
