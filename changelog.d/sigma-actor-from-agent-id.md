section: Changed
---
- **A caller that resolves an agent ID acts as that ID; the acting name no longer decides by its spelling (VantagePeers Cloud).** Marie's Claude.ai person token resolves agent `hélios`; `from="hélios"` was admitted while `from="Helios"` and `from="marie"` were refused. For a caller with a resolved agent ID (credential, seat stamp, personal agent) `from` / `createdBy` / `callerOrchestrator` are now optional in the advertised schema of every tool that declares one; when typed they are refused (`AGENT_IDENTITY_MISMATCH`) only if they designate a DIFFERENT agent ID in the caller's own org directory (`orgRoster:getAgentDirectoryForAccessToken`, already called by the MCP) or are an agent ID the org does not list for the caller, and are otherwise admitted and rebound to the agent's stored label. A directory that cannot be read refuses (fail closed). A caller with no resolved agent ID is unchanged and a formerly required acting name stays required for it (`ACTING_NAME_REQUIRED`). MCP-only: no Convex change, no contract bump. Pinned by `mcp-server/src/__tests__/actor-from-agent-id.test.ts`.
