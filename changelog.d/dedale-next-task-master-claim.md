- **VantagePeers Cloud and Self-host: `next_task` works for a master-scope caller (task k178q6x954qeh4mxh0b4x6sss98jtarn).** A seat whose `whoami` reports `scope_profile` `master` got `RBAC_DENIED` with reason `claimless-service-account` from `tasks:nextForAssignee`: the master bearer resolves no organisation, so the call carried neither `verifiedOrg` nor an agent ID and the backend refused it as a service account with no claim. The MCP now forwards the caller's verified agent ID (`verifiedActor`) on that door for a master scope that has one and has no `verifiedOrg`, so the backend judges it as an agent of the operator organisation. A client-organisation seat still sends `verifiedOrg` only, a Clerk session still sends no claim, and a master with no agent ID still sends none and is refused by the backend. Not changed here: `get_tool_usage` and `get_owner_tool_usage` still refuse a master bearer that carries no organisation or person claim, because their backend doors take no `verifiedActor`; that fix belongs to the backend owner. Pinned by `mcp-server/test/next-task-claim.test.ts`.
