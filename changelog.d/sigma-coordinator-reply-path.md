- **VantagePeers Cloud: a fleet coordinator a client organisation lists can now answer that organisation's roster agents.** The inbound direction (a client agent to a listed coordinator) was admitted, but the reply bounced ("ne correspond a aucun destinataire de l'organisation") because an operator agent's reach was only its own organisation's roster. A sender that is an agent of an active operator org and is listed by client org X (by name in `addressableFleetCoordinators` on the name path, by agent ID in `addressableFleetCoordinatorIds` on the `recipientAgentIds` path, with or without a forwarded proof) may now address X's roster agents, and only those: never via `broadcast`, never for an unlisted coordinator, never to an organisation that does not list the sender, never to an X agent off X's roster (the proven ID path also stops reaching every active agent stamped with X), never mixed with the sender's own roster in one send. The message is stamped in X's tenant and its receipts carry the recipient's agent ID, so the recipient's own inbox read returns it. No Convex argument changes. Evidence: `convex/__tests__/coordinatorReplyPath.test.ts` (12 tests), task k177h2f3nkgns1f1ncf2v160vh8hd5hy.
