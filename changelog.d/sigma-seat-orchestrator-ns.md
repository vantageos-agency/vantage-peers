- **VantagePeers Cloud: a client seat acting for its organisation can store and list memories and episodes in `orchestrator/<its own verified agent ID>`, and only there.** `storeMemory`, `listMemories`, `storeEpisode` and `listEpisodes` take an optional `verifiedActor` (the MCP forwards it to the first three; `listEpisodes` has no tool). Convex judges it with the existing agent-proof check (service account only, an active agent of the acting org by permanent ID) and admits exactly `orchestrator/<that agent ID>` (`seatAgentIdOf`, `convex/lib/seatNamespace.ts`). `orchestrator/<name>` is never a seat's namespace: agent names are unique per org, not fleet-wide, so a client agent named like a fleet orchestrator ("sigma") would otherwise write into that orchestrator's own memory. Another agent of the same org, another org's agent (same name included), a lookalike and a seat with no proof stay refused; master and Clerk members are decided as before. A seat's scope profile must list `orchestrator/<agentId>` (not `orchestrator/<name>`) for the MCP ceiling to let the call through. Backend contract 13 to 14 (a new argument on existing functions): Convex first, read-back, MCP last. Task k1701vj2gxbacdjqr1avpxx7en8hdw2q.
- **VantagePeers Cloud ops: seat profiles list `orchestrator/<agentId>`.** `scripts/provision-client-org-agents.mjs` now registers the agent before minting and puts `orchestrator/<agentId>` (not the name) in the seat token's prefixes; a seat-only bearer gets `project/<org>` only. The new operator script `scripts/seat-profile-agent-namespace.mjs` (dry run by default, `--apply` to write, idempotent) updates the existing client-org profiles through the prod guard only: it reads `oauth:listScopeProfiles` (which now also returns `clerkOrgSlug`), `data agents` and `data client_org_mapping`, and writes `oauth:upsertScopeProfile`; a profile is updated only when its single non-`*` `fromAllowList` entry names exactly one active agent of its own org, everything else is skipped and counted. A token keeps the prefixes it was minted with: a refresh mints from the live profile (measured, `mcp-server/test/seat-refresh-picks-up-profile-prefix.test.ts`), a static 90-day bearer must be re-minted by re-running the provision script (`runbooks/onboard-client-org.md` step 4c). `scripts/prove-cgt-agents.mjs` proves the seat in `orchestrator/<agentId>` (from `whoami`) and that the name namespace is refused.
