- **VantagePeers Cloud and Self-host: `CLERK_DOMAIN` is required, there is no dev Clerk instance fallback (task k17efj6v430bwzvbakb9fjnprh8k0zkf).** The HTTP server's Clerk-JWT layer, `whoami`, and `scripts/lib/org-admin-token.mjs` used to fall back to a built-in dev Clerk instance when `CLERK_DOMAIN` was unset, so a deployment that forgot it would verify tokens against the wrong instance instead of refusing. Now an unset, blank or non-URL `CLERK_DOMAIN` makes the Clerk-JWT layer answer 401 `CLERK_DOMAIN_NOT_CONFIGURED` and fetch no key set (the master bearer and OAuth token layers are unaffected); `whoami` returns `caller_id: null` rather than an id derived from an invented domain; the org-admin script trims the value and refuses whitespace. **Self-host operators must set `CLERK_DOMAIN` to the Clerk frontend API URL of their own Clerk instance**; `deploy/env-manifest.json`, `.env.example`, `docs/self-host/railway-template.md` and the stdio README now list it as required. Pinned by `mcp-server/test/clerk-domain-required.test.ts`, `mcp-server/test/whoami-clerk-domain.test.ts` and `scripts/__tests__/org-admin-token-domain.test.mjs`.
