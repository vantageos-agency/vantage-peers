- **VantagePeers Cloud: every call an OAuth bearer (seat or person token) makes through the MCP now runs inside that bearer's organisation.** Before, such a bearer reached Convex as the fleet service account, which Convex resolves as fleet master, so isolation depended on each tool remembering to forward a `verifiedOrg`; 59 call sites did not, and could return or touch another organisation's rows. The MCP now attaches the bearer's verified organisation ID (read live from its token row's active mapping, never a tool argument) to every query, mutation and action as the reserved `__actingOrg` argument (`mcp-server/src/authenticatedConvexClient.ts`). Convex reads it in one place, the service-account branch of `withOrgScope` (and `fleetStandingOf`), and answers the call as an ordinary member of that organisation: other organisations' rows are never read, fleet-only doors refuse exactly as they refuse an ordinary member (for example `mandates:get`, `mandates:validateSpending`, `fixPatterns:get` raise `RBAC_DENIED`; `profiles:listProfiles` answers its `{ refused: true }` envelope), an inactive or unmapped organisation is refused. The same argument from any other identity is ignored. A bearer whose organisation resolves to no ID gets no Convex client at all. The master bearer, the stdio transport (Self-host) and Clerk-JWT callers are unchanged. Every public function is now built by `convex/lib/functions.ts`, which declares and strips the argument. The `ui://vp/v1/*` resources (`resources/read`), refused to these bearers since the previous fail-closed fix, are now served to a bearer whose organisation resolved, with that organisation's rows only; a bearer with no resolved organisation is still refused with `RBAC_DENIED`.
