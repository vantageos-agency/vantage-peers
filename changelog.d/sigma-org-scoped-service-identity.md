- **VantagePeers Cloud: every call an OAuth bearer (seat or person token) makes through the MCP now runs inside that bearer's organisation.** Before, such a bearer reached Convex as the fleet service account, which Convex resolves as fleet master, so isolation depended on each tool remembering to forward a `verifiedOrg`; 59 call sites did not, and could return or touch another organisation's rows. The MCP now attaches the bearer's verified organisation ID (read live from its token row's active mapping, never a tool argument) to every query, mutation and action as the reserved `__actingOrg` argument (`mcp-server/src/authenticatedConvexClient.ts`). Convex reads it in one place, the service-account branch of `withOrgScope` (and `fleetStandingOf`), and answers the call as an ordinary member of that organisation: other organisations' rows are never read; an inactive or unmapped organisation is refused with `RBAC_DENIED`; the same argument from any other identity is ignored. What a seat does on its OWN rows keeps working: its own profile and summary, its own diary, memories in its organisation's `team/<orgId>` namespace, and the tasks it creates in its own organisation. Doors whose effect is fleet-wide (mandates, fix patterns) stay fleet-only and refuse a seat with `RBAC_DENIED`; a profile write that names another agent is now refused instead of being applied to the caller's own profile. A bearer whose organisation resolves to no ID gets no Convex client at all. The `ui://vp/v1/*` resources are served to a bearer whose organisation resolved, with that organisation's rows only. GitHub owner bindings are read and compared by the organisation's permanent ID (a slug that changed hands no longer carries the former holder's bindings). The master bearer, the stdio transport (Self-host) and Clerk-JWT callers are unchanged. Contract version 11 -> 12: deploy Convex first, then the MCP. Task k179y0wpsd6fv7055f4p2w6b358hdrxe.
