- **The server's public description names what it does, and a long description is served.** `SERVER_DESCRIPTION` (`mcp-server/src/brand.ts`), read by the initialize `serverInfo`, every Server Card path and the `/mcp` landing page, is now the operator-approved "MCP server for multi-agent teams: persistent memory, agent messaging, time-tracked tasks, missions" (98 characters, within the Server Card schema's `description` maxLength 100); `mcp-server/package.json` `description`, previously a different sentence, carries the same text. A new single-source constant `SERVER_LONG_DESCRIPTION` (568 characters, operator-approved) is rendered on the `/mcp` landing page under the short line and is the text for the Claude connector directory submission; it is not added to the Server Card, which has no such field. Two declared maps, `SERVER_DESCRIPTION_CAPABILITIES` and `SERVER_LONG_DESCRIPTION_CAPABILITIES`, tie each capability either text names to the tools that back it (`store_memory`, `recall`, `text_search`, `send_message`, `check_messages`, `create_task`, `start_task`, `complete_task`, `billing_summary_by_project`, `create_mission`, `whoami`). `mcp-server/test/server-metadata-discoverability.test.ts` section 7 pins both texts literally, the length, the equality across every surface and package.json, and that every mapped tool is served by tools/list.
