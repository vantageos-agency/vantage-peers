section: Security
---
- **A seat's organisation is keyed by its permanent ID, not its reusable label (VantagePeers Cloud).** `messages:sendMessage` resolved the forwarded seat org by `seatOrgSlug`, a renamable label: a seat of an organisation that was renamed, whose old label another organisation then took, was scoped as the label's new holder (its roster, its tenant stamp). The door now takes an optional `seatOrgClerkId` beside `seatOrgSlug`; when present it is the only key into `client_org_mapping` (an unknown or inactive ID is refused with the door's existing `RBAC_DENIED`, a `tenantId` is compared to the organisation's current label, and the `verifiedActor` target check is keyed by the same ID). The MCP forwards it from the verified token row's live `orgClerkId`, never from a tool argument. Expand step of the rollout: a call carrying only `seatOrgSlug` (an MCP that predates this) behaves as before; dropping that path is the traced contract step. Backend contract version 9 -> 10, so a new MCP refuses a backend that predates the argument. Pinned by `convex/messages.seatOrgClerkId.test.ts` and `mcp-server/test/seat-org-clerk-id.test.ts`. Rollout: Convex first, read-back, then the MCP.
