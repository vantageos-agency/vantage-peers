- **An agent of org A can no longer act on a task of org B when both orgs have an agent with the same name.** Measured end to end through the MCP tools (convex-test behind the real tool handlers, as the fleet service account): no MCP gate reads the target task, so `complete_task`, `update_task`, `start_task`, `pause_task`, `resume_task`, `block_task`, `fail_task`, `delete_task`, `checkout_task` and `correct_task_segment` all reached Convex and all 10 landed on the org-b row (10 of 10, RED before). The Convex doors `tasks:complete`, `update`, `start`, `pause`, `resume`, `blockTask`, `failTask`, `deleteTask`, `checkout` and `correctSegment` now take `verifiedOrg` (the helper introduced for `bulkComplete`, `convex/lib/verifiedOrg.ts`): honoured from the fleet service account only (any other caller presenting it is `RBAC_DENIED`, never ignored), resolved against an active `client_org_mapping`, and when present the target task's `orgId` must equal it, else `RBAC_DENIED` with no row changed; a row that states no org never matches. The MCP tool for each door forwards the bearer's verified org (agent credential org, else the access-token row's org) exactly as `bulk_complete_tasks` does, from the verified context only: a `verifiedOrg` typed into a tool argument is never read. The fleet master and a Clerk-JWT caller forward none and keep today's behaviour; a person signed in to its organisation (start, update, complete) keeps acting in its own name, with both proofs coexisting. `verifiedActor` alone does not bind a row's org (pinned in mcpNameCollisionVerifiedActor; no transport forwards it alone). mcpNameCollisionExposure 60/60 (REFUSED, PRESENT, MASTER, UNTRUSTED, UNKNOWN, UNSTAMPED per door), mcpNameCollisionVerifiedActor 9/9, taskDoorsVerifiedOrgPerson 12/12, MCP task-doors-verified-org 40/40; dropping the org check on any one of the ten doors turns two poles red (10 of 10 mutants killed). `.backend-doctor/vp-by-tool.csv` regenerated (109 rows) and its row-count guard updated. **A non-master bearer whose org cannot be resolved is now refused at the MCP layer** (no verified actor, no token-row org, not a Clerk session): `RBAC_DENIED` with reason `verified-org-unresolved`, before Convex, on the ten tools, `add_task_dependency` and `bulk_complete_tasks`, per the "a lookup miss at this boundary is a DENY" rule; before, a legacy seat token with no org snapshot reached the name-only check and closed/edited tasks (12 of 12 RED). The fleet master and stdio trust context are unchanged, and a Clerk-JWT caller is scoped by Convex's own org scope (own-org task allowed, foreign-org task refused, measured). task-doors-unresolved-org 24/24; removing the deny turns 12 red, removing it from `complete_task` alone turns that tool red.
