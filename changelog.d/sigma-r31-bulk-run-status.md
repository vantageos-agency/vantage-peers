section: Added
---
- **`bulk_complete_tasks` runs now have a status a client can read, so a failed later batch is no longer silent.** `bulkComplete` closes its first 500 in the call and drains the rest through a scheduled continuation; there is no caller to throw at, so each live run now writes a `bulk_complete_runs` row keyed by the `bulkRunId` the first call already returned (`status` running / complete / failed, `closed`, `remaining`, `failureReason`, `orgId`, `createdBy`). New query `tasks:getBulkCompleteRun` and MCP tool `get_bulk_complete_run`: served to the run's own organisation on the Convex side and, at the MCP layer where the caller is the service account, gated on the row's org and on its creator (`scopeFilterGet`); another org, another creator and an unknown id all answer "not found", and an anonymous Convex caller is refused `RBAC_DENIED`. A later batch that fails (RBAC or closure gate) now records `failed` plus the reason on the row instead of ending as a bare scheduler failure, closes nothing past the refusal, and re-calling the same filter meets the same refusal. The return shape of `bulk_complete_tasks` is unchanged. bulkCompleteSelfScheduled 10/10 (5 RED before) and get_bulk_complete_run 7/7 on the MCP side. **Named and not closed:** a run made through the MCP service account carries no `orgId` (the Convex scope is master), so it is reachable by its creator name only; stamping the actor's org needs an org argument on `bulkComplete`, which is a separate change.
