- **Every door that inserts a task now carries a project, or is refused with TASK_PROJECT_REQUIRED (task k174n9czcs7x77j2hrvqz6n4hh8hrnsb, Cloud and Self-host).** After #1702 only `create_task` / `update_task` refused a missing project; the other insert doors could still write a project-less task that billing then counted in `noProjectCount`. Now refused: the GitHub webhook create, the deploy-task and review-task automations, an OKF import task (its `project` frontmatter, else the `project/<slug>` target namespace, else the import is refused before any write), and a mission template whose mission has an empty project. A recurring schedule must be created with a non-empty project (`create_recurring_task` now requires `project`; `update_recurring_task` refuses blanking it), so every spawn inherits one; a schedule that already exists without one is skipped on each due tick with an explicit log line and a `lastSkipReason`, and nothing is invented. `billingSummaryByProject`'s `noDurationTasksTruncated` is now true only when the no-duration list was cut at its 200-row cap, not when a row lacked `completedAt`.
