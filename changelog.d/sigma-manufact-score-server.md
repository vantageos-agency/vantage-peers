- **VantagePeers Cloud and Self-host: the MCP server describes itself.** `initialize` / `server/discover` now carry `title` ("VantagePeers"), `description` and `websiteUrl` in `serverInfo`, plus server `instructions` (<= 2048 UTF-8 bytes: call `whoami` first, identity comes from the sign-in, address agents by `agentId` from `list_peers`, `create_task` needs a `project`). One source of strings: `mcp-server/src/brand.ts`. Pinned by `mcp-server/test/server-metadata-discoverability.test.ts` and `mcp-server/test/server-metadata-byte-budget.test.ts`.
- **VantagePeers Cloud: public discovery.** A public MCP Server Card (experimental-ext-server-card schema v1, validated in the test against the vendored `schema.json`) is served unauthenticated at `/mcp/server-card`, `/.well-known/mcp/server-card.json`, `/.well-known/mcp-server-card`, `/mcp.json` and `/.well-known/mcp.json`, on the origin the request was served on. Opening `/mcp` in a browser (no `Authorization`; `Accept` absent, `*/*` or text/html; no `text/event-stream`) returns a setup page; every MCP request on `/mcp` is unchanged, including the 401 + `WWW-Authenticate` that starts OAuth (both poles pinned).
- **VantagePeers Cloud: MCP Apps view metadata.** All 12 `ui://` views declare `_meta.ui.domain` (the served HTTPS origin, none on stdio or plain http) and `openai/widgetDescription`; the six tools with a view carry `openai/toolInvocation` labels. The `bulk_complete_tasks` description is 1864 bytes (was 2766) so Claude Code no longer truncates it; its behaviour is unchanged.
