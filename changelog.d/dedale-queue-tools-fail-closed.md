- **VantagePeers Cloud and Self-host: `reorder_queue` states who can call it over MCP, and `reorder_queue`, `next_task` and `list_tasks` `sort: "queue"` refuse a broken backend reply instead of defaulting (task k17c5xftwzvtts05ban1dhxazs8jv4h6).** The 5.0.0 entry for `reorder_queue` says it is open to an organisation admin. Through MCP that is not so: a person bearer carries no verified actor, so the backend door refuses it, and an organisation admin sets a queue from a signed-in session, not through this tool. Over MCP the callers that succeed are the assignee agent itself and a listed queue coordinator; the tool description and the README now say so (the 5.0.0 history is left as written, this entry is the correction). Separately, `reorder_queue` no longer fills a missing `ranked` or `cleared` from the request, `next_task` no longer reads a null or shapeless reply as "No pickable task", and `list_tasks` with `sort: "queue"` no longer reads a non-array reply as an empty queue: each now fails with `BACKEND_SHAPE_MISMATCH`, naming the tool and the backend door, and says the outcome is unknown. An explicit `{ found: false }` still returns `found: false`. Pinned by `mcp-server/test/queue-tools.test.ts`.
