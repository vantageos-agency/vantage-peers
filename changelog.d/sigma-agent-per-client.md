- **A person holds one agent per AI client, and the token acts as the agent chosen at consent.** Several agents bound to one person in one organisation is valid (one for Claude, one for ChatGPT, one for Grok). The consent screen lists every agent already bound to the person (plus unbound agents and a create field for an org admin only; a member still never takes an unbound agent, refused server-side) and always offers "Connect as myself", the default. The chosen agent ID is stored on the authorization code and stamped on the minted person token (`oauth_access_tokens.agentId`; additive optional `oauth_person_codes.agentId` and `connectedAs`). `oauth:getAccessTokenByHash` acts as the stamped agent only while it is still active, still in the token's organisation and still bound to the person; otherwise as the person, never as another agent. The operator door `agents:setPersonalAgentOf` no longer refuses a second agent for the same person. Existing person tokens carry no stamp: they keep acting as their agent only when exactly one agent designates the person, and act as nobody when several do, until the person reconnects and chooses. Backend contract stays 8 (no MCP-called function or argument changed; 8 was never rolled out). Task k176wqmafpq7asbh461g95tk7h8hbsmy.
