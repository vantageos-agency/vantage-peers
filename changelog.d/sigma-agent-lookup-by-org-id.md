section: Security
---
- **The agent-by-name lookup is bound to the organisation's permanent ID, not its slug (VantagePeers Cloud).** `findAgentByName` selected agents by `orgSlug`, a renamable label: an organisation that took a slug released by another resolved the previous holder's agent by name (its ID was stamped as a task assignee, and the sender, recipient and profile-label checks matched it). It now selects on the `clerkOrgId` indexes (`by_org_normalized_name_clerk_id`, `by_org_name_clerk_id`) with the verified org ID where the caller holds one (seat scope, mapping row) and the ID the slug's mapping row stores otherwise. An agent row with no `clerkOrgId`, and an organisation whose mapping carries no ID, resolve nobody (refused, not matched by slug); a renamed organisation finds its own agents under its current slug. Convex only, internal signature, no public argument or return change, no schema change. Pinned by `convex/__tests__/findAgentByNameSlugTakeover.test.ts`. Prod must be counted for `agents` rows with no `clerkOrgId` before deploy.
