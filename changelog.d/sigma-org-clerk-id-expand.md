- **Org identity by Clerk org ID, expand phase (VantagePeers Cloud).** Pi ruling (d): an organisation is its permanent Clerk org id (`org_...`), never its slug, which is a renamable label. `client_org_mapping.clerkOrgId` (optional, indexed `by_clerk_org_id`) is now the source of truth, set by the internal `clientOrgMapping:setClerkOrgId` (refuses a malformed id, an id owned by another mapping, and a silent change) and filled by `scripts/fill-mapping-clerk-org-id.mjs` (dry run prints the inventory first, `--target dev|prod` required, the Clerk secret goes to curl through a 0600 config file, never a command line). 17 tables that store an org as a slug gain an optional id column beside it (`clerkOrgId`, or `tenantOrgId` next to `tenantId`) with an id-leading twin of every slug-led index (`<name>_clerk_id`; `tasks` omits the plain `by_orgId` twin to stay at 31 of the 32-index limit). `migrations/backfill_org_clerk_id` fills them from the mapping by slug: paged, dry run by default, idempotent; a slug with no mapping, an ambiguous mapping, or a mapping whose id is not filled yet is left unfilled and listed by row id, never guessed. New writes (messages, receipts, missions, tasks, diary, briefing notes, business units, recurring tasks, bulk-complete runs, agents, relations, credentials, access tokens) stamp slug and id from the mapping of the verified org. No comparison changes here: every door still compares slugs until the lanes switch to ids. `backfillOrgClerkId.test.ts` 16/16, 5 stamping tests RED without the write-site edits.
