- **VantagePeers Cloud: the organisation the MCP verified for a bearer is keyed by its permanent Clerk ID, not its slug.** The `verifiedOrg` claim (the 17 task, briefing-note, diary, business-unit, KB and tool-usage doors) named the organisation by slug, a renamable label: an organisation that was renamed lost access (its old slug names nothing), and a slug another organisation took over reached the former holder's rows (`bulk_complete_tasks` matched rows by the slug stamp). The claim now carries `orgId`; Convex resolves the mapping through `@vantageos/cloud-identity` (`resolveOrgFromClaim`, ID-keyed), narrows rows by their stored org ID, and looks the asserted caller label up among that organisation's agents by ID (`callerActorOf`). `get_fix_pattern` now sends the verified agent's ID and `fixPatterns:get` compares it with the pattern creator's agent ID instead of matching a creator name against the bearer's roster, so a client organisation's agent bearing the operator's label no longer reads the operator's patterns. Expand phase: the slug-only claim is still accepted (the MCP live today sends it), so refusing it is a later contract step.
