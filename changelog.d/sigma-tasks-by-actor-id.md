section: Security
---
- **Task doors decide on actor IDs, never on names (module M7).** `start`, `complete`, `update`, `blockTask`, `failTask`, `pause`, `resume`, `correctSegment`, `deleteTask`, `bulkComplete` and `attachReviewArtifact` compare the verified caller's agent ID with the row's `createdById` / `assignedToId` / `lastAssignedToId`; two agents with the same label in different orgs no longer see or mutate each other's tasks, and a renamed agent's old label names nobody. `tasks:create` stamps `createdById` from the verified caller and refuses an assignee that is not an agents row of the task's org (`RBAC_DENIED`, `assignee-not-an-agent-of-org`). `list`, `listPaginated` and `listOverdue` filter by assignee ID (new indexes `by_assigneeId_project_status`, `by_assigneeId_status_updatedAt`, `by_orgId_assigneeId_status`, `by_orgId_assigneeId_project_status`). Deploy order: run `migrations/backfill_task_actor_ids` first (dry run by default, paginated; ambiguous or unknown labels are listed, never guessed), because a row without IDs names nobody. Evidence: `convex/__tests__/tasksById.test.ts` 30/30 (25 red before the change), `convex/__tests__/backfillTaskActorIds.test.ts` 5/5, `convex/__tests__/scopeHelpersById.test.ts` 9/9.
