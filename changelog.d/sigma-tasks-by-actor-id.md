section: Security
---
- **Task doors decide on actor IDs, never on names (module M7).** `start`, `complete`, `update`, `blockTask`, `failTask`, `pause`, `resume`, `correctSegment`, `deleteTask`, `bulkComplete` and `attachReviewArtifact` compare the verified caller's agent ID with the row's `createdById` / `assignedToId` / `lastAssignedToId`; two agents with the same label in different orgs no longer see or mutate each other's tasks, and a renamed agent's old label names nobody. `tasks:create` stamps `createdById` from the verified caller and refuses an assignee that is not an agents row of the task's org (`RBAC_DENIED`, `assignee-not-an-agent-of-org`). `list`, `listPaginated` and `listOverdue` filter by assignee ID through the two step-1 indexes `by_assigneeId_project_status` and `by_assigneeId_status_updatedAt` (no index is added or removed; `tasks` stays at 32). An org member's assignee label is resolved inside the member's own org and the resulting ID is proved to be an agents row of that org before any read (`RBAC_DENIED` otherwise, an unknown label stays an empty success); rows stamped for another org are dropped by the tenant gate (and, on `listPaginated`, by a residual `orgId` filter inside the scan). Reading an assignee without `project` now reads the whole status bucket (bounded by the 2000-row scan cap, `SCAN_CAP_EXCEEDED` beyond it) and orders by creation time afterwards; `listPaginated` by assignee is ordered by `updatedAt` desc. Deploy order: run step 1's `migrations/backfill_task_actor_ids` and its read-back first (dry run by default, paginated; ambiguous or unknown labels are listed, never guessed), because a row without IDs names nobody; then deploy this change. Evidence: `convex/__tests__/tasksById.test.ts` 34/34 incl. the cross-org stray-row pin, `convex/__tests__/backfillTaskActorIds.test.ts` 5/5, `convex/__tests__/scopeHelpersById.test.ts` 9/9.
