- **VantagePeers Cloud: a token's rights follow its scope profile as it is now, not the copy made when it was minted.** `oauth:getAccessTokenByHash` returned the `fromAllowList` / `namespaceRead/WritePrefixes` snapshot on the token row, so when a seat profile gained `orchestrator/<agent ID>` (c5348d65, efbc6193) every live seat token kept the old copy and was locked out. It now derives them on every request from the live scope profile row (a person token: the live organisation mapping, as `rotateRefreshToken` already did); a profile that is gone, or that now names another organisation, grants the token nothing. A token whose mint asked for less than its profile is flagged `rightsPinned` (decided on Convex by comparing the request to the profile row, never taken from the caller) and keeps the copy as a narrowing: intersect, never wider than the profile. Additive: no argument or return shape changes (`MCP_CALLED_FUNCTIONS` and the contract version are untouched; deploy Convex, no MCP change needed for this part). New: `convex/lib/tokenRights.ts`, `migrations/tokenRightsDrift:inventory|stampPinned|revertPinned`, the rule `.claude/rules/rights-change-migrates-live-connections.md` and `scripts/check-rights-change-note.mjs` (also item 6 of the PR self-gate). Behaviour change: an operator mint (`/admin/oauth/access-tokens`) can narrow below its profile and no longer widen above it.
