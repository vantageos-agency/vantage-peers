- **VantagePeers Cloud: the backend now records which MCP tools each caller has used, per organisation, and `get_tool_usage` reads it back.** Every tool call that resolves (success or tool error, never a scope refusal) files one row per (organisation, caller, tool) with the tool name, first call time, last call time and a count; no argument, content or secret is stored. The caller is a person (`user:<Clerk subject>`) or an agent seat (`agent:<agent id>`), derived from the verified identity on the request, never from a tool argument; the master bearer is not recorded. `get_tool_usage` returns `{tool, firstAt, lastAt, count}[]` for your own usage, for any caller of your organisation if you are an organisation admin (or fleet operator, who names the organisation), and raises `RBAC_DENIED` for another organisation or another caller without admin standing. `get_owner_tool_usage` returns the same shape aggregated over everything a person owns in its organisation (every agent that designates the person, plus the person's own direct calls): earliest first call, latest last call, summed count; the owner reads itself, an organisation admin, the fleet and the organisation-scoped service caller (the onboarding engine) read any member of that organisation, a plain member reading another member and an owner outside the organisation are `RBAC_DENIED`. Recording is fire-and-forget: a recording failure never fails a tool. New table `tool_usage`, new Convex doors `toolUsage:record`, `toolUsage:getToolUsage` and `toolUsage:usageByOwner`; contract version 13 -> 14 (`BACKEND_CONTRACT_VERSION`, `REQUIRED_CONTRACT_VERSION`): roll out Convex first, MCP last.
