- **The Pi merge guard judges every route to a merge, not only the words `gh pr merge` (task k17cm51e8c1m3qv0w45pxybmx18jxsnr).** `enforce-pi-authorization-before-pr-merge` exited 0 with no Pi token for `gh api -X PUT repos/<o>/<r>/pulls/<n>/merge`, for the GraphQL `mergePullRequest` / `enablePullRequestAutoMerge` mutation through `gh api graphql`, and for `gh alias set mm 'pr merge' && gh mm <n>` (an alias defined in the same command, or read from the gh config). The guard now also reads `gh api` write calls on the merge endpoint, the GraphQL merge mutations, curl / wget / httpie PUT, POST or PATCH at api.github.com, and aliases that expand to any of those or to `pr merge`. Each merge found is judged by the same reviewer-verdict gate as `gh pr merge`, so a Pi token over a REVISE is refused on every route. A payload the guard cannot read (a shell variable as the method, endpoint or query) is refused.
