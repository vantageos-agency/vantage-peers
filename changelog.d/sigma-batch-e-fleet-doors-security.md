section: Security
---
- **A non-master bearer acts for its verified organisation on the repo-mapping and owner-binding doors (VantagePeers Cloud, batch E).** `githubRepoMapping:getByRepo`, `add`, `remove` and `githubOwnerBinding:listBindings` declare `verifiedOrg`, believed from the fleet service account only (`convex/lib/verifiedOrg.ts`); `add_repo_mapping`, `remove_repo_mapping`, `get_repo_mapping` and `get_github_owner_bindings` forward the bearer's verified org and refuse a bearer whose organisation they cannot resolve before Convex. Before, a non-master bearer reached those doors as the fleet service account, so `add_repo_mapping` wrote a FLEET row and `get_github_owner_bindings` listed every organisation's bindings. The fleet master still forwards no org and is unchanged.
- **The fleet-internal write doors are service-account-only by purpose, said by the package's standing.** `issues:updateStatus / linkCommit / verify`, `errorMonitor:addDeployment / removeDeployment` and `fixPatterns:create / addAttempt / validate / linkIssue` no longer read a master flag: the standing is `scopeWithFleetStanding` (cloud-identity), refused by `requireResolvedCaller` (`masterOnly` + `mcpBoundOnly`) and by the package's `requireServiceAccountStanding`. The inventory now records their writer tier as `fleet-internal` (it read `org-member` / `master`).
- **`issues:createExternal` assigns an agent by ID.** It takes `assignedOrchestratorId` (an agents-row ID), judged by the package (active, of the operator organisation); a same-label agent of a client org is another agent and is refused. The display label is read from the row.
- **`errorMonitorFilters:listFilterRules` asks the package for the fleet standing** instead of reading `scope.isMaster`; an ordinary member is still served the typed empty list.
- **Deploy order.** The claim is a new OPTIONAL argument on four Convex doors that the MCP starts sending: deploy Convex first, then the MCP. An MCP that sends `verifiedOrg` to a Convex that does not declare it is refused `ArgumentValidationError` for every non-master bearer on those four tools (the master forwards no org and is unaffected either way).
