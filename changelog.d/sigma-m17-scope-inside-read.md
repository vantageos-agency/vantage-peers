section: Security
---
- **The caller's tenant is applied inside the read, never after an unscoped one (R-11).** Eleven MCP doors (`list_messages`, `search_messages_by_keyword`, `list_broadcast_status`, `get_message`, `list_tasks`, `search_tasks_by_keyword`, `list_bus`, `list_briefing_notes`, `search_briefing_notes_by_keyword`, `list_repo_mappings`, `get_episode`) forward the bearer's verified org and their Convex doors run under that org's member scope, so a foreign row is never read; `get_fix_pattern` forwards the bearer's roster and `fixPatterns:get` gates on it before reading attempts. Pagination (`nextCursor`) is derived from the scoped read, not from the rows a narrowing filter kept. `episodes:getCriticalInsights`, `stats:openTaskCountsByOrchestrator`, `tasks:listUnlinkedBlocked`, `businessUnits:list` (new index `by_orchestrator_status`) and `briefingNotes:list` with `updatedSince` read the member's own tenant range. `stats:fleetStats` is now the fleet master's: an org member is refused `RBAC_DENIED` (`not-fleet-master`) instead of being served every tenant's counts. Evidence: `convex/__tests__/scopeInsideRead.test.ts`, `mcp-server/test/scope-inside-read.test.ts`.
