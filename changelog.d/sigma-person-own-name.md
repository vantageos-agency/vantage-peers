- **A person connected through Claude.ai or ChatGPT writes in its own name.** With a person token (#1444) and no acting name, `create_task`, `update_task`, `start_task`, `complete_task`, `send_message`, `create_mission` and `update_mission` act as `user:<Clerk subject>` read from the token row, never from an argument. The MCP server forwards only `verifiedPerson: { accessTokenHash }`; the Convex door (`convex/lib/personPrincipal.ts`) believes it from the service account alone, re-reads subject, organisation and role from the live token row and an active organisation mapping, then runs the dashboard's unchanged human path (`resolveHumanActor`: writer role, tenant, admin). A viewer is refused `role-not-writer` at both layers; naming an agent still needs its credential; naming another person is `PERSON_ACTS_AS_ITSELF`; any other write tool with an acting name answers `PERSON_NO_HUMAN_DOOR` by declaration (`personDoor`). Agent registration, rename and seat provisioning now refuse a name starting with `user:` (`AGENT_NAME_RESERVED`). Tests: `mcp-server/test/person-writes-own-name.test.ts` (11, real authorize flow), `convex/__tests__/verifiedPersonBridge.test.ts` (19).
