- **VantagePeers Cloud: `erase_memory` (MCP tool) and the Convex erase doors behind it, a real erase path for a credential pasted into a memory.** `softDeleteMemory` only flips `isLatest`: the body stays readable by id and the RAG entry keeps the original text. The tool replaces the matching text in the stored body, recomputes `contentHash`, then re-indexes the RAG entry under the same key and purges the superseded chunks. Admitted, for a row whose stored org ID is the caller's own: an organisation ADMIN (any memory of the org), or a MEMBER for the memories it authored itself (stored `createdBy` equals the verified actor name `user:<subject>`). Two public doors: `memories:redactMemoryContent` (a Clerk-JWT bearer's own session) and `memories:redactMemoryContentAsPerson` (a person bearer, forwarded as `verifiedPerson`, the bearer hash). The typed refusals (`RBAC_DENIED`, `REDACT_NO_MATCH`, `MEMORY_NOT_FOUND`) reach the client unchanged. The fleet keeps its reach over every org through the internal `memories:redactMemoryContentFleet` (operator `convex run`). Backend contract version 17 to 18, 212 backend functions: deploy Convex first, then the MCP.
