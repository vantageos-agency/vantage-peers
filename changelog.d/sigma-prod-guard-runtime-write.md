- **Prod-write guard: a Convex write whose URL is assembled at runtime is judged on its action and its target.** `enforce-pi-authorization-before-prod-deploy.py` matched only a literal `https://<name>.convex.cloud/api/mutation` in the command text, so `python3 -c` with `os.environ["CONVEX_URL"] + "/api/mutation"`, an f-string, a variable host (`H=...; curl "$H/api/mutation"`), `urljoin`, `node -e` with `process.env.CONVEX_URL + '/api/mutation'`, and a heredoc program (`python3 - <<EOF` or `bash <<EOF`, whose body was stripped before judgement) were all allowed. The action is now decided by `runtime_write_vector()` and `heredoc_programs()` in `.claude/hooks/_lib/command_predicate.py`: an HTTP client or interpreter that reaches a Convex surface and writes, including a heredoc body that a shell or an interpreter runs as its program. The target is resolved from what the station can name: a literal host, a `CONVEX_*URL` variable (inline or in the environment), the prod name, or the dev name in `CONVEX_DEPLOYMENT`. A write that does not resolve to dev is refused, and a write provably to dev passes. A dev deploy key or a read-only marker cannot excuse a runtime write on the same line. Pinned by `.claude/hooks/tests/test_prod_guard_runtime_write.py` (30 poles, both polarities, run on the real hook). Task k17bx73va6s36bg1qdqw0enjch8f97h2.
- **Prod-write guard: versioned and path-qualified interpreter heads, and decoy dev hosts, no longer pass.** `python3.12`, `/usr/bin/python3.14`, `node22` and the other versions of a runtime family now walk the same head test (`runtime_family()`, reusing `_strip_version_suffix`), and a write is dev only when every URL source it uses (each literal host and each variable read) resolves to dev, so a dev host string beside an unresolved `os.environ['DEPLOY_HOST']` no longer certifies the write. Pinned by the family poles in the same test file (55 poles in total). Task k17bx73va6s36bg1qdqw0enjch8f97h2.
