- **VantagePeers Cloud: the OAuth metadata now advertises the `offline_access` scope.** OpenAI documents that ChatGPT may lose access to a connector whose authorization server does not advertise it. `scopes_supported` is now `["mcp:full", "offline_access"]` in the authorization-server document (`/.well-known/oauth-authorization-server`), the protected-resource document (both URLs) and, with `openid` and `email`, the OIDC discovery document. A request naming `offline_access` at `/authorize` was already accepted (this repo sets no `supportedScopes` list on the package) and is pinned as accepted. Security: it grants nothing. `/token` drops `offline_access` from the minted access token's scopes, so the token's authority is byte-identical with or without it. Changed: nothing else. The person (authorization_code) flow issues no refresh token today, with or without `offline_access`, and this change leaves that as it is; the refresh_token grant still serves only refresh tokens already held. Fixed: nothing. MCP-only change, no Convex function or contract-version change; ships by the operator's Railway redeploy after merge (`.claude/rules/railway-mcp-redeploy.md`). Tests: `mcp-server/src/__tests__/oauth-metadata-offline-access.test.ts`.
