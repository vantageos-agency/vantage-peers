- **An invalid cursor argument now carries a stable machine code.** The thirteen advertised tools that take a `cursor` (`list_episodes`, `list_peers`, `list_messages`, `list_tasks`, `list_missions`, `list_diaries`, `list_briefing_notes`, `list_recurring_tasks`, `list_repo_mappings`, `get_github_owner_bindings`, `list_fix_patterns`, `list_memories`, `list_tasks_by_mission`) answer a cursor that does not decode with `isError: true` and `structuredContent: { error: { code: "invalid_cursor", message } }`, through one helper (`invalidCursorResult`); the text is unchanged (`Error: invalid cursor: ...`). Every other error result still carries no `structuredContent`; rule 6 of `mcp-server/src/outputSchemas.ts` now names this one exception (mcp-standard C-11 (b), SEP-1303). `get_github_owner_bindings` now hands out opaque cursors (`nextCursor`, `unprovenNextCursor`) wrapping the Convex cursor, so an invalid one is refused before any Convex call; a raw Convex cursor from an earlier call is refused as invalid. Accepted limit: a client on the v1 TypeScript SDK (`@modelcontextprotocol/sdk@1.32.2`, `client/index.js:493`) validates `structuredContent` against the output schema even on an error, so it may report a schema mismatch instead of the `invalid_cursor` error; the call fails either way, only the message differs, and the output schemas are unchanged (a root union would break SDK v2). No Convex function or argument changed: no contract bump. Task k171rk9evy8yy48tfx765zqwk18hwdvh.
