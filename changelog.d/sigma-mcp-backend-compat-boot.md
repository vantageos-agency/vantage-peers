- **The MCP server refuses to boot against a Convex backend that lacks a function it calls.** On 2026-10-12 the Railway MCP auto-deployed `main` (calling `oauth:rotateRefreshToken` and passing new arguments) while Convex prod was an older build, and clients failed for hours. New public query `meta:backendContract` (`convex/meta.ts`, service account only, names only, RBAC_DENIED for anyone else) returns the contract version and the generated list of public function identifiers (`convex/lib/backendManifest.ts`, `node scripts/gen-backend-manifest.mjs`). `server-http.ts` and the stdio `server.ts` call it before binding a port or opening a transport; a missing manifest, an old contract version or any missing function in `MCP_CALLED_FUNCTIONS` logs `BACKEND INCOMPATIBLE (<reason>)` naming the functions and exits 1, so Railway keeps the previous deployment. Both lists are pinned to their sources by tests. Rule and runbooks now say: Railway auto-deploy is OFF, Convex first, the MCP last under the rollout token. Evidence: `mcp-server/test/backend-compat-boot.test.ts`, `convex/__tests__/backendContract.test.ts`.
