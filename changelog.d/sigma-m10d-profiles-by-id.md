section: Changed

- **Profiles belong to an agent ID, not to a label (module M10d).** `profiles.agentId` (an `agents` row ID, index `by_agent`) now decides who a profile is. `profiles:getProfile`, `getProfileWithMemories`, the profile half of `dashboard:getDashboardSummary` and an acting agent's `listProfiles` keep a row only when its agent belongs to the caller (`filterTargetsBelongingTo` for an agent, `sameOrg` for a member); a same-named agent of another organisation and a row with no agent are served to no member. `upsertProfile` and `updateDynamic` are written only by the owning agent (`verifiedActor` from the service account, or its own `agentCredentialSecret`) and find its row by agent ID; the `orchestratorId` argument selects nothing. The fleet service account keeps its existing grants and `listProfiles` keeps its refusal contract. The MCP forwards `verifiedActor` on the three actor-bound profile doors. Operator step 1, run before this reaches production: `migrations/backfill_profile_agent_ids:run` (dry run by default; an unknown or ambiguous label is blocked, never guessed). Evidence: `convex/__tests__/profilesById.test.ts` 36/36; backend-doctor 0.4.2 R-53 246 -> 243, CR-2 246 -> 244.
