- **`list_blocked_on_me` MCP tool and `tasks:listBlockedOnMe` read: a responder sees who is waiting on it.** For each live task assigned to the caller, lists the `blocked` tasks that cite it through `blockedOnTaskId` (`blockedTaskId`, `blockedTitle`, `blockedAssignee`, `onTaskId`, `onTaskTitle`, `age`) plus `total`, `oldestAge` and `truncated` (bounded scan, never a silent partial set). The reader comes from the verified identity (same resolution as `check_messages`), a blocked row outside the reader's tenants never appears, an anonymous caller is refused with `RBAC_DENIED`, and an empty result is a real absence. A dedicated opt-in read: `check_messages` still returns messages only. Additive: the new function is in `MCP_CALLED_FUNCTIONS` and the generated backend manifest (no contract-version bump). Tests: `convex/__tests__/listBlockedOnMe.test.ts`, `mcp-server/test/list-blocked-on-me.test.ts`.
- **Fix (review k17dh7c87cahraa1n45d5e2a0n8gz98d):** `computeBlockedOnMe` selects the caller's live tasks by assignee agent ID (`by_assigneeId_status_updatedAt`; name-keyed `by_assignee` only as the declared fallback for a reader without an agent ID) and judges every row with `taskVisibleTo` instead of a hand-written tenants check. Pinned by two new poles in `convex/__tests__/listBlockedOnMe.test.ts` (relabelled-by-ID task found; cross-org row not returned).
- **`list_blocked_on_me` serves the verified agent by ID only (review round 2, task k17dh7c87cahraa1n45d5e2a0n8gz98d).** `tasks:listBlockedOnMe` refuses (`RBAC_DENIED`, reason `blocked-on-me-needs-agent-id`) a reader that carries no agent ID (a bare label: org member naming a recipient, org-name, fleet, operator-admin) and the claimless service-account call (reason `claimless-service-account`); a verified agent, or a service account carrying `verifiedActor`/`verifiedOrg`, is served. The MCP tool drops its `fromAllowList` speak-as gate: `recipient` is a hint that grants nothing. Breaking for label-only callers of this new, not-yet-released read.
- (round 2) The MCP tool forwards neither `recipient` nor an organisation: only a seat's `verifiedActor` reaches Convex; an org-level token or the fleet master is refused by the backend.
