- **Tool inputs say what a value means; the schema says how it validates, and the two no longer disagree.** Defaults moved from the prose into the input schema (`default` on 36 `limit`, `fields`, weight and TTL fields), and no description restates a default, bound, enum list, pattern or requiredness its schema already carries. The 16 inputs that change nothing (`fields` on 14 tools, `list_blocked_on_me.recipient`, `import_okf_bundle.idempotencyKey`) are still accepted, now marked `deprecated` and described as having no effect; each is proven unread by a test. A `fields` switch that does change the output names what `lite` and `full` return. `import_okf_bundle` mode `replace` is described as what it does today (the same as `merge`), `export_okf_bundle` format `tree` as refused. `get_task`, `get_briefing_note` and `get_recurring_task` carry one list of returned fields, each a stored field. Titles: `set_summary` "Set my status summary", OKF tools name the namespace bundle. Tool names, types, constraints and runtime behaviour are unchanged.
