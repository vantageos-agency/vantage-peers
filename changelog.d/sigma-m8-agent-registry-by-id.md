- **Agents and agent credentials are resolved by agent ID, never by a name (Cloud, module M8; operator rule: identity by ID).** `agents:setAgentAddress|deactivateAgent|reactivateAgent|renameAgent|getAgent`, `agentCredentials:mintAgentCredential|revokeAgentCredential|getAgentCredentialStatus` and `agentRelations:linkChild|unlinkChild|childrenOf|parentsOf` take `agentId` (`parentAgentId`/`childAgentId`) instead of a name; `registerAgent` creates a row, returns its ID and refuses a label already held (`AGENT_NAME_TAKEN` naming the holder by ID, `AGENT_INACTIVE` for a retired one) instead of updating it. Identity is decided in `@vantageos/cloud-identity` 0.12.0 (pin `^0.11.0` to `^0.12.0`, root and `mcp-server`): org admin through `resolveActingPrincipal` + `assertOrgAdmin`, the target agent's organisation through `assertTargetBelongsTo` (another organisation's ID is `RBAC_DENIED`, never returned), a presented secret through `validatePresentedBearer` + `requireAgentScopedIdentity` + `resolveActingPrincipal`, hashing through the package `sha256Hex`. Deleted from `convex/lib/agentIdentity.ts`: `resolveAgentCredentialCore`, `credentialRowsOfAgent`, `legacyCredentialRowsByLabel`, `bindLegacyCredentials`, `assertNoOrphanLegacyCredentials`, the local `sha256Hex`; from `convex/agents.ts`: `assertAgentNameUsable` (the reserved `user:` check is the package's `isPersonActorName`). Kept, flagged `@deprecated` and named, not deleted: `findAgentByName`, still called by `convex/lib/auth.ts` (3 sites), `convex/messages.ts` (2), `convex/lib/actorIds.ts`, `convex/lib/seatAgent.ts` and `convex/lib/inboxReader.ts`, which turn a typed label into an agent for legacy name-typing surfaces; no door of the three registry files calls it. The dashboard's `components/agents/*` call the renamed args by name and must ship the ID shape first or in step.
