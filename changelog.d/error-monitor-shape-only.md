- **VantagePeers Cloud and Self-host: the error monitor files shape-only public issues, and no longer stops silently (task k17ahr4dz3rm0tgr09ah28bbh18g6xhb).** The monitor is corrected, not paused. An auto-filed GitHub issue now carries only the function name(s), the error class and code prefix (for example `ConvexError` / `RBAC_DENIED`), the deployment, first and last seen, the count and the repo `file:line` of the throw. It never carries the message sentence, `Path:` / `Value:` argument echoes, row contents, ids or stack message lines; the raw text stays in the private `errorLogs` row. `redactIssueBody` and `redactIssueTitle` map an existing value-echoing issue to the same shape (code only; no GitHub call). Every silent stop path of the poll, issue and auto-resolve loop (missing deploy key or `GITHUB_TOKEN`, log fetch error, unparsable log or cursor, GitHub non-2xx or thrown, missing issue number, kill switch, deploy window, deployment cap, a failed linked-PR check) now writes a console.error with a stable code and a durable `errorMonitorConfig` row, read through `errorMonitor:listMonitorHealth`; the record never carries a secret or a log value. A failed linked-PR check no longer reads as "no PR". An auto-closed error or an externally closed issue no longer writes `completionOutcome: "succeeded"`; the note states "no recurrence observed since <time>" or "closed by <actor>". `dashboard:getDashboardSummary` returns only the profile fields its validator declares (#1423). No schema change.
