- **Task doors, recurring schedules and review routing decide on agent IDs; their reads narrow before they bound.** A member's acting agent and an assignment target are held to the org's agent-ID roster (`allowedAgentIds`) instead of the name list; `createdBy` filters, the search `assignedTo` filter, the review-reassign and automation-cancel grants and the bulk-complete `assignedTo` filter resolve a label to ONE agent ID in ONE organisation, so a same-named agent of another org gets nothing; `recurringTasks` assignees are agents recorded under the label their row carries. `tasks:list`, `listPaginated`, `listByMission`, `listOverdue`, `searchTasksByKeyword`, the billing and duration reads and `recurringTasks:list` apply the roster, priority, cursor and `active` predicates while the range is read, so a page is full instead of short (R-55); a scan that reaches its cap before the page is full refuses `SCAN_CAP_EXCEEDED`.
