- **A write made through the fleet-master seat is stamped with the operator organisation, and a fix pattern can be erased.** A memory, mission, task, diary entry, briefing note, recurring task or business unit written by the fleet master carried no organisation, so `erase:eraseRow` refused it `target-unstamped` and nothing could take it back. Such a write now carries the permanent ID of the one active operator organisation (derived from the `orgKind: "operator"` mapping, never typed; a team namespace keeps the ID it names; with no operator ID the row stays unstamped). Rows already written are handled by `migrations/fleetWriteStamp`: `count` (numbers only, unstamped rows per table), `run` (dry run by default; stamps a row only when its author is an agent of the operator org and of no other) and `revert` (exact, by the stamped ids). New MCP tool `erase_fix_pattern` over `fixPatterns:erase` (an operator-org admin only, as for any row with no author ID; RBAC_DENIED otherwise) and internal `fixPatterns:eraseFleet`.
