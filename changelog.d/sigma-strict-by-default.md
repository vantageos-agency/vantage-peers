section: Security
---
- **The MCP server is strict by default: a typed agent name without an agent credential is refused, except a seat acting as itself.** `VANTAGE_ACTOR_CREDENTIAL_MODE` absent or empty now resolves to `strict` (`/health` source `unset` / `empty`); `permissive` is reached only by setting it explicitly. Under strict, a non-master caller naming an agent without `x-vantage-agent-credential` gets `AGENT_CREDENTIAL_REQUIRED`, with one exemption read from the OAuth token row: a `fromAllowList` of exactly one name (not `"*"`), no `principal` on the row, naming that same name. Multi-name bearers, a seat naming another agent, person tokens and Clerk-JWT sessions are refused; a valid credential naming its own agent is served. `strict_would_refuse` no longer counts a seat naming itself. A person token (#1444) composes as: writer-role gate first, then this check; a person editor naming an agent needs its credential, reads naming no agent are served. The seed-profile refusals now carry codes (`AUTH_NAMESPACE_DENIED`, `AUTH_SENDER_WILDCARD_DENIED`). Tests: `mcp-server/test/strict-by-default.test.ts` (18 cases), `mcp-server/test/person-token-writer-role.test.ts` (pole 4 on a real person token), `convex/__tests__/clientScopeProfilesAreData.test.ts`.
