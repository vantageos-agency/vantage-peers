- **The MCP recurring-task tools forward the acting agent's `verifiedActor`.** `create_recurring_task`, `update_recurring_task`, `pause_recurring_task`, `resume_recurring_task` and `delete_recurring_task` now reach `recurringTasks:create` / `update` / `pause` / `resume` / `remove` with the agent ID the seat or credential resolved to (`mcp-server/src/verifiedActor.ts`). Without it a seat of a client organisation reached Convex as the service account, its assignee was looked up in the operator organisation and `create` was refused `assignee-not-an-agent-of-org`. The service account that forwards a verified agent is judged on that agent's ID on update / pause / resume / remove: a same-named agent of another org is refused, and a schedule with no actor IDs is refused with `schedule-without-actor-ids` until `backfill_recurring_task_actor_ids` has run (it runs before the rollout); the service account with no forwarded agent keeps its access. Roll out the backend (M10h, additive optional argument) before the MCP. Evidence: `mcp-server/test/recurring-verified-actor.test.ts` 18/18, `convex/__tests__/recurringTasksVerifiedActor.test.ts` 18/18.
