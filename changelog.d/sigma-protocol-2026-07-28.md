- **The VantagePeers Cloud MCP server speaks protocol 2026-07-28 (ChatGPT MCP Events, OpenAI forms) and still speaks 2025-11-25 to Claude.ai, Claude Code and Codex.** The server moves from `@modelcontextprotocol/sdk` 1.x (whose latest, 1.32.0, still tops out at `LATEST_PROTOCOL_VERSION = '2025-11-25'` and has no `server/discover`) to `@modelcontextprotocol/server` 2.3.0. HTTP `/mcp` is served by `createMcpHandler` over the same per-request factory (verified caller and Convex client closed over, no session), and stdio by `serveStdio`: a 2026-07-28 client is answered on `server/discover` (supportedVersions + capabilities) and served per request, a 2025-era client still negotiates its own version through `initialize`. Tool behaviour is unchanged: over all 79 advertised tools, `tools/list` is identical before and after except two protocol fields, the JSON Schema dialect stamp (`$schema` draft-07 to 2020-12, SEP-1613) and the dropped `execution.taskSupport` (task wire vocabulary deprecated in 2026-07-28); initialize capabilities, resources and resource templates are byte-identical. A modern `tools/list` carries `ttlMs`/`cacheScope` (SDK default `0`/`private`). No tool elicits, so there is nothing to move onto the multi-round-trip mechanism. A tool-thrown protocol error now reads without the v1 `MCP error <code>:` prefix (`ProtocolError` replaces `McpError`). `defineTool`, the person-token role gate and annotation derivation are untouched. Evidence: `mcp-server/test/protocol-2026-07-28.test.ts` 6/6, red 2/5 on 8cfa2bf (the v1 server answers `server/discover` with HTTP 400 `-32000 Unsupported protocol version: 2026-07-28`).
